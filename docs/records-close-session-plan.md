# 业务记录：接下来怎么收（待你点头）

这页只讲准备怎么做。没说继续之前，不改产品。

不写死业务种类、表名、字段、动作、年份。词表和图是结构的唯一来源。闸只校验，不做理解。

## 工作台现在怎么认「完了」和「正式结果」

它理解的单位不是「一轮对话」。它理解的单位是「过闸的那一次」。

- **它拿什么当「处理完了」：** 不当。工作台不听「这一轮对话结束了」。左边转不转，是聊天窗口自己的事；转停了，只表示这轮字说完了，工作台不拿这个当完。
- **它拿什么当「正式结果」：** 待上桌的那张表变了。模型每过一次闸，就往这张表里写一次。工作台轮询看见变了，就往右边画。所以它心里的正式结果 = **最近一次过闸写进去、又没被挡住的那张表**。写操作多一个确认令牌，那是给你点过账用的，不是「这一轮结束了」。

一句对话里可以过闸好几次。工作台每一次都可能当成正式结果去画。它没有「这一轮的最终结果」这个判断。

右边**不是**左边做完了推一张正式结果过来。是主动去拉一个共享的「待上桌」槽：左边模型过闸时往这个槽里写；工作台大约每秒问一次这个槽，变了就往右边画。工作台有时自己还会再打一枪预览，也写进这个槽。所以右边跟的是槽里最新那次，不是「这一轮结束时左边交出来的那张」。

依据：[收口总因](records-close-root-cause.md)（一句话不是一次 bind）。

## 所以右边会跟错

是。一句请求里可以有好几段条件、好几次分析。模型会把思考写在左边会话里。每分析对一截、过一次闸，就可能往「待上桌的表」里写一次。工作台认不出哪一次才是这一句的最终结果，右边就可能跟上中间那一截，而不是这一句真正要给人看的那张。

左边会话可以有过程。右边的表只该跟这一句最终要确认的那张。现在两套没分开，所以会跟错。

## 准备怎么处理

不经过 AI 会话就能处理好的，不动。只修：左边会话和右边的表配不上。

现网错在：右边听槽变化来画表，判断不了结束点。  
要改成：会话说这一轮结束了，就把这一轮的结果交给右边。不听槽，也不在停转之后再去读槽里最新那张。

1. **接会话的结束点。** 结束以会话自己为准，不以槽变了为准。
2. **交这一轮的结果。** 这一轮里模型可能过闸好几次，都写进同一个槽。槽里最后一次往往是模型自己又查的，不是这轮要给你看的。交给右边的，是这轮的结果，不是槽里最后那一次。
3. **过程不画。** 这一轮还没结束，右边保持上一轮。
4. **模型自己再查，不能拖住这一轮。** 「自己」是模型，不是你。它没等你再说话就又去查，会让左边一直转，这一轮关不上。关不上就不能把表交给右边——所以必须让它关得上，不是接受右边一直空着。
5. **不经过会话的功能原样留下。** 行内改行、过审、取消、点历史现在都不走左边会话，保持这样。

这一轮如果不是在操作业务数据（只是闲聊、问事），会话结束时没有业务表可交，右边保持原样，不换、不清空。

上一刀旁支是「停转后再读槽」，那还是读槽，作废，不进 main。

不写死业务种类。不推远程。不关正在跑的界面。三块印证过了再对抗审查。

## 根本原因（左和右配不上）

不经过 AI 会话就能处理的功能，保持原样。这个问题只谈：左边 AI 会话和右边的表配不上。

**现网：** 右边盯的是共享「待上桌」槽变了没有。槽一变就画。它不是在收「这一轮结束 + 这一轮的结果」。所以它判断不了结束点，也会画成过程里的某一次过闸。

**会话自己：** 知道这一轮何时结束，也知道这一轮产出了什么（这轮的工具结果）。工作台现在不收这两样。

**正触发：** 一轮结束时，把这一轮的结果交给右边。不是听槽变化，也不是停转之后再去读槽里最新那张。

先前把「现网读槽会读错」写成好像模型本身有问题，那是搅在一起了。不经过会话的功能不是这个问题的一部分。

## 你说的对：表跟哪一轮结果

对。右边那张表，跟的是：**你这一句处理完之后，模型交回来的那张结果表**。

你再发一句 → 模型再处理完 → 右边换成**这一句**交回来的结果。没处理完，表不该自己先跳。

现在拧的地方：处理你这一句的时候，模型还会在同一条对话里**自己再查几枪**（不是你又说了一句）。这几枪也会交回一张表。系统把它们当成「又一轮处理完了」，把右边换掉。所以你会看到：你没说话，表自己跳了；或者跳到的不是这一句该交的那张。

准备改成：只有「你这一句处理完交回来的结果」能换表。同一句里模型自己再查的，不能换表。

## 「补查打完，左边必须停转」是什么意思

左边 = 聊天窗口。转 = 一直显示「深度求索中」。

补查 = 你这一句的结果已经出来了，模型还在同一条对话里自己再查。不是你又发了一句。

这些自己再查的枪，会让聊天窗口以为这一轮还没结束，所以一直转。

准备改成：你这一句的结果已经上桌，聊天窗口必须停转、把这一轮关掉。不是把验证再等多一会儿。

## 「倒 20 行目录」是什么意思

不是你倒的，也不是业务库自己倒的。

是工作台在查的时候，如果这一枪没有筛条件，就会按默认页大小拉一页列表（现在是 20 行）。这是后台自己补的一页，不是你下的新口令。

它为什么会动到右边：这 20 行被当成「又一轮处理完了」，把你这一句该留着的表盖掉。

准备改成：这种自己拉的一页列表，不能换右边的表。不把 20 写进产品逻辑；页多大跟词表/查询走，不写死行数。

## 跳关联表

你一句里要看「这个和它关联的那个」：走词表里已经发布的关系，跳到关系指向的那张。

不写死跳哪一种业务。例子里出现过的名称，只是当时词表里有的关系，不是代码里的特例。

## 已经对的别弄坏

后台自己再查，不能盖掉你正在改的那一行。空结果不能把表抹掉。你下一句处理完，必须换成那一句的结果。

不推远程。不关你电脑上正在跑的界面。

## 准备怎么验

不验「某一种业务好不好使」。验的是工作台认不认一轮、认不认正式结果。

每次还要核准确率：右边交上来的行，必须符合这一句的条件。只核功能能跑、不核行对不对，不算过。

以前一条对话连打十几句，上一句的过程会污染下一句，看不出是契约坏了还是会话脏了。所以只打三块，每块看一件事。

说什么话：打开现场词表，用里面已有的对象和关系说话。不把任何业务名写进验证脚本。下面用「第一句 / 第二句 / 有关系的那一句」称呼，不指定种类。

### 第一块：同一条对话里你说 2～3 句

目的：右边跟的是「这一轮结束时的正式结果」，不是过程里过闸的那一次。

怎么做：

1. 开业务记录，用**同一条**对话。
2. 发送第一句（现查或词表里有的动作都行）。等左边这一轮停转。
3. 看右边：应是第一句的结果。
4. 再发送第二句（和第一句不是同一件事）。等左边这一轮停转。
5. 看右边：应换成第二句的结果，不能还停在第一句。
6. 有需要再发第三句，同样：停转后右边是第三句。

过程里怎么看「自己再查不换表」：某一句发出去之后、左边还在转的时候，右边如果先跳到另一张表（尤其是没筛条件的一页列表），再跳回来或停在那页，就算没过。停转之后，右边必须是你这一句要的那张，不是过程里闪过的那张。

过：每一句停转后，右边 = 这一句。转的时候不跟丢、不跟成自己再查的表。  
没过：你没说下一句，表自己换了；或下一句停转后还是上一句的表。

### 第二块：正式结果上桌后，左边必须停转

目的：一轮结束这个信号是真的，不是表先画了、聊天还以为没说完。

怎么做：就用第一块里某一句已经停转、右边已经是正式结果的那一刻。看左边聊天。

过：正式表已经在右边，左边没有「深度求索中」，输入框可以再发。  
没过：右边表有了，左边还一直转。把等待再加长不算过。

### 第三块：新开一条对话，说一句带关系的现查

目的：跳关联表走词表里已发布的关系，而且是这一轮的正式结果；不是后台自己拉的一页目录。

怎么做：

1. **新开**一条对话（不要接着第一块那条，避免上一轮的过程还在）。
2. 在词表里找一条已经发布的关系：两种对象是连着的。
3. 说一句现查，把这两个都点出来（「这个，和它关联的那个」这种）。
4. 等左边这一轮停转。看右边。

过：右边是关系指向的那张，并且带着这一句的条件，不是某种对象的默认第一页。  
没过：右边是没筛条件的一页列表；或跳到的不是词表关系指向的那张。

不在脚本里写死「必须是某一种」。现场词表没有关系，这一块记「词表没有可验的关系」，不编一种业务来验。

这三块都过了，再做对抗审查。对抗审查也只攻契约，不写死业务名。
