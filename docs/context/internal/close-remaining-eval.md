# 收口剩余评测类（规定，不准另发明）

源计划：[业务数据评测](/cursor/stores/bc-aea46619-2327-43a7-a094-57e6e76a7d7e/docs/biz-data-eval.md)

## 原则

- 结构只来自词表+图+schema。闸不是 NLU。
- 禁止写死 kind / action / field / year / table / relation / page size / 中文名 / 80 / 15 / 11 / 4 / 120 / 12 / ±1。
- 官方表行数和页脚「共 N 条」必须对上独立库数，不是屏幕行数。
- 空集已知 0 写「共 0 条」，不是「总数未知」。
- overlay：`cp` 后只 `connect`，禁止 `reload`，禁止动 5174/4318 端口，禁止杀现有进程。
- 每一类先独立库数 + 现网截图，再改；改完只测该类。一类证据不齐不准接下一类。
- 删掉因此无用的代码。不为「灵活」加配置。

## 顺序（必须）

### 1. 自环

- 员工「X的X」：官方表是一条已发布自环边的命中（现网曾是下属 15），**对侧边必须是 chip**（现网库数管理者 80），禁止整表 120，禁止空表。
- 部门自环：同样机制；库数曾是 11/4，禁止整表 12，禁止把子级 4 做成 12。
- 做法：同 kind 上多条已发布自环边 = 图上的多条边。官方表走其中一条；其余边做 peer chip；每条边的 `hitTotal` 来自该边过滤后的 `:list` `meta.count`。不要写死 manager/subordinates。

### 2. hop 差 1

- 已知偏离（只作验收对照，禁止写进代码）：采购收货单 386/385，订单明细 2088/2085，工单处理记录 800/798。
- 禁止用 ±1 或名单凑数。查 hop 链接主键/过滤/分页为何丢掉行，修到与独立库数一致。

### 3. `{{t()}}` 跨对象边

- Users / Roles / Departments 等词表名被 `{{t("…")}}` 污染，边对不上。
- 在匹配/发边前还原或中性化显示名。禁止写死这三个英文名。
- 已有 prompt 里 `{{` 零宽中性化；这边是词表/图匹配，不是再补一层 prompt 技巧就完。

### 4. 串行换表

- 仅当前三类图审材料齐（截图 + 独立库数）之后。
- 362 必须串行，禁止 8 路并发。替换官方表。
- 换表前把 [业务数据评测](/cursor/stores/bc-aea46619-2327-43a7-a094-57e6e76a7d7e/docs/biz-data-eval.md) 写到当前类状态。
