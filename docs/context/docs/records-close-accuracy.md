# 结果和条件对不对（待你点头）

只读旁支 `dfb28ab`。没改产品。

## 这刀有没有写死业务词

没有把领用、归还、报废、调拨、固定资产、资产领用归还写进代码。

它还不通用。三处特殊还在：

1. 和一个更长种类名开头相同的词，会被丢掉。
2. 枚举不一定归到拥有它的那个种类，会归到话里附近的另一个种类。
3. 写死了一串字段名（status、state、type、状态、类型等）。字段上没有枚举，也会当成条件。

## 行数够不够全

没有枚举标签的关系现查，交上去的是默认的一页，不是全部命中。

页脚「共 N 条」是这一页留下的行数，不是业务库的总数。N 正好等于这一页的大小时，不能当成全部。表自己再按 10 条翻页，那个页码也不是业务库的总页数。

「现查员工档案关联的考勤记录」只是这种请求的例子。图上 20 条、1 页，不能证明真的只有 20 条。

## 还会交错行的情况

- 关系现查里没有枚举标签：一页就当正式结果。
- 枚举不属于这句话点到的种类：条件没加上，仍是那一页。
- 枚举只打在目标表上：没挂这条关系的行也会进来。
- 同一字段上两个标签是「或」：对上其中一个就进来。不是两个同时成立。
- 闲聊：不换表，右边留着上一轮。
- 行内改行、过审、取消、点历史：仍不走左边这一轮。

## 根本原因

两件是同一根：正式结果被当成「这一页预览」，条件被当成「话里的词碰运气对上」。

**不够通用。** 正路是：这句话里的词，如果是某个已点到种类上的枚举值，就加到那个种类上。现在中间有三道猜测：像更长种类名的前缀就丢掉；归到话里附近的种类，不是拥有这个枚举的种类；一串写死的字段名没有枚举也算条件。所以有的话加上了，有的加错种类，有的不该加也加了。

**行数不够全。** 查的时候按一页去取，取满就停，不记业务库的总数。这一页只要带着关系路径，就被当成正式结果。页脚把留下的行数印成「共 N 条」。N 等于一页大小时，看起来像全部，其实是截断。表再按 10 条翻页，页码也不是业务库的总页数。

## 是不是词表和图不够

不全是。缺属性和没用上已有属性，是两件。

对象名不是属性。名称里带了某个词，不等于这个对象声明了这个属性。能拿来筛的，是词表里这个对象的字段，尤其是枚举。能拿来跳的，是图上已经发布的关系。

词表或图缺了，这句话就没有可执行的条件：对象没有这个枚举字段，或两个对象之间没有这条边。这时不能从名字里猜一个属性，也不能编一条边。缺的要从连接器的表和字段补进词表和图，不是在工作台写死。

属性已经在词表里、边已经在图上，仍然会不准：工作台没按它们用。枚举被猜到别的对象上，关系只用了第一页的编号，有边却把边丢掉只拉目标表。再给对象加一个同名属性，修不了这些。

## 上一版改法缺什么

上一版只说「枚举加到点到的种类」和「把全部行交出去」。两头都浅。

短名长名撞词、一个条件对上多个对象，按那版会加错或丢掉。把命中全部灌进右边，数据一大就会慢、会撑满，生产上站不住。页脚照样可能把截断说成全部。

## 先绑对象，再绑条件

一句话先在词表里绑对象，用最长名称。被长名占住的那一段字，不再拆成条件，也不再当成另一个短对象。

剩下的字才去对枚举。枚举加到**拥有它、并且这句话已经绑上的每一个对象**。不加到没绑上的对象。不加到「附近那个」。

同一段字只绑一次。长对象名优先于枚举，也优先于更短的对象名。

### 短对象名和长对象名里有相同的词

说的是长名：只绑长对象。短名里的那几个字是长名的一部分，不是条件，也不是第二个对象。

只说了短名，词表里短的和长的都是对象：短名若是长对象的别名，绑长对象。两个都是独立对象、这句话又分不清：沿用模糊命中，先选再继续，不默默挑长的，也不把短名当成条件。

对象名里面夹着枚举词：那些字已经被对象名占住，不再当成额外条件。要收窄，得是对象名之外又说了的条件。

### 一个条件对上多个对象

这个条件在几个已绑对象上各自有枚举：每个对象都加上，各管各的行。

只在其中一个对象上有：只加那一个。

两个对象都有，但是不同字段、对不上是不是同一个意思：不加，也不要猜一个字段。这句不能假装已经按这个条件筛过。

同一字段上多个值仍是「或」：对上其中一个就留。两个值互相排斥又被说成必须同时成立：结果就是空，空要显示成空，不能偷偷丢掉一个值去凑行。

### 同一条规则覆盖的其他情况

- 别名不是第二张表，也不是条件。
- 一句话一条关系链：交的是整条链上的命中，不是链的某一头单独一页。
- 否定（不要某种状态）只认词表里的枚举否定，不靠「最后两个字」去猜。
- 条件和关系都有：行要在关系上，并且符合它自己那个对象的条件。不能只按条件把整个目标表拉下来。
- 闲聊没有业务表：不换、不清空。
- 行内改行、过审、取消、点历史：仍不走左边这一轮。

自由文本、日期、金额，这页不新做一套理解。对不上词表枚举和图的，不能编一个条件。

## 行数：命中要全，表可以翻页

不准把命中的每一行都一次灌进右边。那样会慢、会撑满。

准的是命中集合：

- 关系的上游不能只用第一页的编号去找下游。上游被截断，下游就是错的，不只是少显示。
- 右边可以一页一页看，但每一页都是同一个命中集合。翻页不能换成另一次没条件的查询。
- 页脚总数是这个命中集合的总数，不是这一页的行数。
- 查询有上限时，到了上限必须标明不完整。禁止把上限印成「共 N 条」好像已经全了。
- 业务库给不出总数，就标明未知，不拿留下的行数充总数。

不写死种类、字段、枚举值、页大小。不推远程。不关正在跑的界面。
