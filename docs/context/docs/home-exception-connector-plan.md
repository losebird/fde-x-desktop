# 首页异常和待启用：怎么收

对照 [首页那个 1 和待启用](home-exception-connector.md)。点头之前不改。

首页上的数，必须能点到同一本账里的那一行。连接胶囊认的「已接通」，必须是这条连接真的在干活。不写死工单、不写死局域网适配器。

## 1. 那个 1

权威是人能看见、能点开的那本操作账。首页红字只数这本账里还要人看的失败。

演练没打到业务系统、已经结束的，不是异常。不要再把 `uncertain` 的演练算进红字。

现在那条 `TK20260305892` 演练：红字应回到 0。不要为它另开一页。操作记录仍是局域网写入痕迹，不要把演练硬塞进去冒充写过库。

以后真失败：红卡能进操作记录里的那一行。点不开的计数不算收完。

## 2. 待启用

权威是这条连接现在能不能干活。源系统已经在查、在写，胶囊就是已接通。首页「已接通」读同一个字段。

`pending` 只表示还没接通。通了就要改成 `connected`。现查、改行成功，或适配器已在线且健康，都算通了。断了再改回去。不要只种一次 `pending` 就再也不改。

不要另做一套「其实已经通了」的显示，和库里的 `status` 并排。

## 你怎么验

点头改上之后。首页异常待处理是 0。点红卡：没有那条点不开的演练。操作记录里仍能看到 CUST2056 那些真写入。连接胶囊是已启用/已接通，首页已接通是 1。断掉适配器再看，应回到未接通。

## 按这个改，会不会把现在能用的弄坏

**现查、改行、过账、设置保存、MCP、词表都不会坏。** 会变的是首页那两个数字，以及给 AI 看的一句「离线」。

灯（`business_connections.status`）现在只有两处在认这个值。首页「已接通」和「待启用」胶囊认它。给 AI 拼上下文时，不是 `connected` 就在连接名后面加「（离线）」。现查、改行、过账走局域网适配器自己的钥匙，不读这盏灯。设置「保存连接」只写适配器的 json。MCP 页的「在线 / 已登记 lookup」看的是适配器在不在、钥匙在不在，不看这盏灯。词表也是保存连接时另走的。所以把灯改成已接通，或断了改回待启用，不会把这些开关拨掉。灯闪一下，查和写还在。

红字只在首页那张卡上数。全仓库只有演练结束时会把操作写成 `uncertain`，没有第二处。操作记录、写审计不数它。不把演练算进红字，大红字从 1 变成 0。小字「1 次操作留有记录」仍是 1，因为它数的是全部操作，不是异常。那条演练还在库里，只是不再涂红。真失败、回退失败仍算进红字。
