# 运行环境 IM 行：怎么收

对照 [运行环境 IM 行为什么还待接通](runtime-im-pending.md)。点头之前不改。

这行认的「接通」，必须是这条 IM / 业务操作能力现在能不能干活。有插件目录，不等于接通。现查、改行已经能走，这行就不能再写尚未接通。不写死适配器名、不写死目录文案。

首页那盏灯刚按「现在能不能干活」收过。这行不要另做一套「其实已经通了」。和灯认同一句活信号。灯绿、这行还黄，不算收完。

## 1. 三个状态

权威是现在能不能干活，不是目录在不在。

- 插件不在：不可用。
- 插件在，但钥匙没配好、适配器不在线、活调用走不通：待接通。这句话必须是真的还没通，不能再当默认句。
- 现在能干活：正常。现查、改行成功，或适配器在线且健康且 lookup 已配，都算通了。断了再回到待接通。

不要再：目录在 → 固定 degraded → 固定「运行时调用尚未接通」。

## 2. 不要另起一盏灯

`GET /health` 的 IM 项和首页胶囊读同一条「现在能不能干活」。不要健康检查一套、连接表一套、设置表单再一套。

现查、改行、过账、设置保存仍走它们自己的钥匙，不拿这行当开关。这行只报事实。

## 你怎么验

点头改上之后。适配器在线、现查能走：这行是正常，首页已接通还在。点重新检查仍是正常。适配器断了：这行待接通，灯也未接通。插件卸了：这行不可用。现查、改行、过账、设置保存不被这行挡住。
