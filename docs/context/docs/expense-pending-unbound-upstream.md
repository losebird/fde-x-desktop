# 为什么现查条件最后只剩「收成外键 id」

这一路不是给枚举或文本列准备的。9 月 24 日下午把「口语外键收成 id，没收成就别当已绑」接进了现查条件的唯一名单。名单后面那道闸从 9 月 18 日就在：条件还在、名单空了，就不要整表现查。闸当时看的是「列名没对上」。接进去之后，对上了的枚举和文本列被当成没对上列名。

写入那边当晚改成了按格子分三种：照写、枚举、指向另一行。现查这支没改，还是只吐 id。按列去比（今早）只改了槽，没改这支。所以现在有三处都能决定「这条 where 留不留」，最后拍板的是外键那支。

对照上一篇现象：[待审费用报销没查出来](expense-pending-miss-root.md)。没改代码。

## 1. 当初只管口语外键

`c184266b`（9 月 24 日 17:41）新建 `relation-bind.js`。提交写的是：m2o 槽走目标表收成外键 id，patch 和 where 都收；没收成的口语外键从预览令牌里拿掉。过审的下一状态改从枚举线索来，不写死文案。

函数从第一版就扫全部 where，不是后来才扫全的。留下的值只有两种：已经是纯数字的 id，或者在 `m2o/o2o/belongsTo` 上对上唯一一行。文件头就写「schema 上的 m2o，不靠 spoken.json 的外键白名单」。测试也只有这一件：客户名「恒通」收成 id `99`。

同一笔提交把它插进 `probeOne`，位置在 `bindClueEnums` 之后、空名单闸之前。枚举对齐的结果要再过这一遍才算数。

## 2. 非关系格被删，是因为失败语义抄了外键

内层「这列不是关系就看下一列」只跳过当前 key。外层是「有原值、却一个 id 都没收到，整段不要」。这是 patch 上「口语外键没绑上就别写进令牌」的同一句话，用到了每一段 where 上。非关系列永远走不进收 id，于是也被当成没收成。

没有「不是关系就原样留下」这一支。从出生就没有。

谁让它当「where 留不留」的权威：它改写的是 `probeOne` 里那份 `clues.terms`。后面的空名单闸只读这份。槽里的枚举命中、文本列保留，写进同一份名单，再被它重写。重写之后没了，闸分不出「列名没对上」和「值已绑上、被外键规则扔掉」。

`1c5f7dd9`（9 月 24 日 22:15，口语外键那刀）给 **patch** 加了 `bindSpokenCells`：照写、枚举、指向另一行，各走各的。枚举唯一就留下 code。现查函数只把「一个 id」改成「可以多个 id」，「没 id 就整段不要」没动。写入和现查从此不是同一套收口。

## 3. 空名单闸认的是列名，不是已绑的枚举

`d2868f40`（9 月 18 日）加的 `WHERE_UNBOUND`。提交写的是：条件对不上 schema 列时收紧；别让一次没绑上的现查变成无筛选整表。hint 是「筛选条件没对上词表列名，不能整表现查」。当时名单前面只有对键和枚举对齐，再滤掉对不上列的项。空了 = 列没粘上。

9 月 24 日把外键收口插到这道闸前面，闸的字没改。已收成 `status=待审` 的项被拿掉之后，看起来和「列名没对上」一样，于是拒绝整表。闸不会把已经对齐的枚举留回去。它的职责是「有人要筛选、筛选没成形，就别倒全表」，不是「枚举绑上了就查」。

`termFitsCollection` 对得上 `status` 也会留。它排在外键收口后面，看不到已经被拿掉的项。

## 4. 和问题描述是不是同一叠

分两截。

更早那次（DSH 86898，[按问题描述删为什么对不上](delete-by-description-miss.md)）不是这叠。整句在进查找之前就被 `modelWhereAgreed` 丢掉，因为那时文本列也要值先是枚举命中。剩下的「胡文」去查了客户名称。那篇写明了：不是「收口后一条都不剩」的 `WHERE_UNBOUND`。

按列去比落地之后是这叠。`f515b03c`（9 月 25 日 02:08）让点了列名的文本列留下，去格子里先等值再包含。这次没改 `relation-bind.js`。同一会话 turn 14（DSH 99009，[这轮为什么突然停](delete-turn-stop-root.md)）工具 where 已经是 `description` /「问题描述」加那整句，回执仍是 `WHERE_UNBOUND`。文本列在槽里留下了，进了同一份名单，被只吐 id 的那支拿掉，9 月 18 日的闸把它当成列名没对上。

## 5. 现在是三处都在管「这条 where 留不留」

同一用户结果：右边按这句话查出费用报销或问题描述那几行。

| 谁 | 当初管什么 | 现在还能不能单独留下 where |
|---|---|---|
| 槽里的枚举命中，加上 `bindClueEnums` | 话里的枚举收成 schema code | 能写进名单。最后不算 |
| 按列去比（`f515b03c` 的槽和 `where-pass`） | 点了名的文本列去库里的格子比 | 能写进名单，标成文本。最后不算。外键文件没跟着改 |
| `bindWhereRelationTerms` | 口语外键收成 id；没收到就别装成已绑 | 名单的最后一写。只留下 id。这一处就能让上面两处作废，并触发「别整表现查」 |

按 [同一职责不并排](../principles/one-authority-no-copies.md)：外键收口那件别的事还在，不该整段删。能单独否决「这句话的现查」的，是它被接进现查名单、又沿用了「没 id 就不要」。写入已经有按格子的三分类。现查的权威还停在外键收口上。
