# Qwen 慢：能收什么、不必收什么

对照：[Qwen 为什么特别慢](qwen-slow-runtime.md)、[Qwen 21 行出了回合不收](qwen-turn-not-end.md)。点头之前不改。

## 先说清楚

硅基上 Qwen3.8-27B **单步推理就是慢**。9 分 12 秒里大约 550 秒在等模型，工具大约 2 秒。这一点工作台变不成快模型。

能收的是 **104 秒表已经出来之后还转的 7 分钟**：查完又 preview、长 reasoning 枚举 20 行、不 `turn/end`。这是 agent 环，不是算力。

## 该做（正路）

现查已经 `ok`、有 `hitTotal`、表已上台：

1. **回执把总量说清。** speak 带「共 N 条，本页 M 条」，不要只说「最近一页 20 条」。模型才不会去补第 21 条。
2. **同一句、同一 hop 不要再打 `biz_preview`。** 再打回同一张表。不写死工单/21。
3. **官方表已结算就收口。** 模型继续想或补查，当 leftover：该说的话说完，不要再开工具环。人要翻页另说。

词表+图，不写死待审/停用。决策 22：没出表的失败路径仍允许多步；明确「下一页 / 第 21 条」仍可再查。

## 不必做 / 捷径

- 不靠 prompt「想短一点」。
- 不把测试改成只用 grok。
- 不取消思考。
- 不拿超时硬掐当修好（会切掉真的慢工具）。
- 流式只能让等待看得见，不缩短 282 秒那一步。

## 你怎么验

Qwen 新会话「停用客户还有哪些没关的工单？」：表上台后 **一两句内 `turn/end`**，不要再打两遍同款 preview，总时长应接近「出表 + 一句说明」，不应再接近 9 分钟。现查仍是 21 行交集。
