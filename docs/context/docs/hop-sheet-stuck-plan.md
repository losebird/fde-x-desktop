# 右边只跟这一句查到的表

对照 [工单查到了右边仍是改行](hop-sheet-stuck-root.md)、[右边为什么长出两张当前表](hop-sheet-stuck-upstream.md)。点头之前不改。

左边这句拿到哪些行，右边就是同一张表。见 [五问 §9](records-panel-decisions.md)。现查、改行、删除、过审、新建共用。不写死工单、客户。

指定一份权威：**这一句已经查到（或要确认）的那张表。** 查到了就上台。上一句的表让开。

大厅（给 AI 马上说话）、同一句里先别把半中间那次刷上去、重连把未确认的改行还回来、点了浮现历史就停在那一次——这些别的事还在，留下当投影。不能再各自决定右边画哪张。

## 收成什么样才算好

1. 「恒通电子有哪些工单？」查到 4 张，右边马上是这 4 张工单，不是上一句的客户改行。
2. 同一句里连查好几次：半中间的目录、空表，不得盖掉这一句已经对上的表。最后对上的那张上台。
3. 改行抽屉还开着、令牌没用：重连仍是这张改行。人已经在问下一句现查，改行让开，现查上台。不得用改行挡住这一句的工单。
4. 点了浮现历史：停在那一次。后面的推送要带上这一次的编号。没有编号不得把一张真的新现查当成「不是这条」丢掉。

## 和现有功能

不改这些已经能用的：

- 新开会话、只查一种、等话说完再看：本来就对，改完立刻对，不会更坏。
- 同一句里连查好几次：半中间的目录、空表，仍不能盖掉这一句已经对上的表。
- 改行抽屉还开着、令牌没用：重连仍拿回这张改行。
- 点了浮现历史：停在那一次。后面的推送不能把人拽回最新表。

增删改审的确认抽屉还是未使用的令牌做主。这一句要确认的改行/删除/过审/新建，马上上台。同一句里写预览后面跟着的无身份现查，仍不能盖掉抽屉。下一句现查才能让上一句改行让开。

会按下葫芦浮起瓢、必须跟这一刀一起收的：

1. 人已经在问下一句现查：上一句没确认的改行要让开。不能为了保改行，把这一句的工单/明细挡住。
2. 新表必须带上这一次的编号。没有编号不得把一张真的新现查丢掉。
3. 写成功后的跟进现查：带着刚写下的身份才上台；无筛选整表仍不能当回执。

## 不要第三套

不要再加第五份「当前表」。不要特赦工单或恒通。不要整段拆掉大厅或回合——AI 说话和同一句过滤还要用。

## 你怎么验

点头改上之后。同一会话先停在客户改行，再说「恒通电子有哪些工单？」：右边马上是这 4 张工单。同一句里若再打出空目录，右边仍是这 4 张。点浮现历史里的改行，表回到那一次客户；再问工单，又换成工单。
