# 和 Palantir 比，准确性还差什么

讨论用。不是修复计划，也不改产品。Palantir 这里只按他们公开的本体模型说，不猜内部实现。

修复仍以 [业务记录修复计划](records-close-fix-plan.md) 为准。

## Palantir 靠什么把行算准

准确性不是模型「更懂业务」。是这句话必须先变成本体里已经有的结构，对不上就不执行。

本体里先有三样：

- **对象**：有类型。能筛的是这个对象上声明过的属性，包括枚举。显示名里的字不是属性。
- **关系**：对象和对象之间的边，事先定义。顺着边走，不是临时猜。
- **动作**：参数、校验、提交条件都先定义好。要改数据，走这个动作，不是直接改表。

查询是一个**对象集**：哪些对象、哪些属性条件、沿着哪条边。这个集合有自己的总数。界面可以翻页，翻的是同一个集合，页脚不是第一页的行数。

模型和人一样，只能提出这个对象集或这个动作。类型、属性、边对不上，执行前就拒绝。不会从名字里补一个不存在的属性，也不会把第一页当成全部命中。

写之前还有提交校验。人确认的是已经校验过的那一次动作，不是模型中途某一次猜测。

## 我们已有的

方向相同：词表是对象和属性，图是关系，闸只认词表和图里有的。写要先预览、人确认、再凭令牌过账。口语短名是别名，不是第二张表。

## 还差的

按对准确性的影响排。

1. **读没有「对象集」这一关。** 话没有先收成「哪个对象、哪个属性、哪条边」再去查。对不上就拒绝这件事，读路径上没有。现在是话里的词去碰，碰错了也交出一张表。
2. **属性没有成为筛的唯一来源。** 对象名里的字会被当成条件。枚举会归到附近的对象。还有一串写死的字段名，没有枚举也当条件。
3. **关系走不全。** 上游只用第一页的编号去找下游，下游就是错的，不只是少显示。
4. **总数和本页没分开。** 「共 N 条」是留下的行数。N 等于一页大小时，看起来像全部。
5. **正式结果没有和这一轮绑死。** 右边听的是槽里最新一次，不是这一轮收成的那个对象集。
6. **词表缺了就猜，而不是拒绝。** 对象没有这个属性，或图上没有这条边，仍可能交出一张表。Palantir 这种会直接不执行。缺的应该从连接器补进词表和图，不能在查询时编。

写路径上的预览令牌，已经接近他们的动作提交。差的主要在读：读还不是一个校验过的对象集。

## 不照搬的

不把他们的产品搬过来。不新做自由文本、日期、金额的理解。对象集对不上词表和图，就拒绝或标明这句没有可执行的条件，不编一个。
