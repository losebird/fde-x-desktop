## 收成什么样才算好

1. 人话里要进库的值按 schema 这一格收。已绑的确认面是解析后的那一行（或照写的这句话、或唯一枚举），不是口语装作已绑。未绑要提示这一格对不上。可空可以空着过，必填未绑确认不能过。不许静默丢掉键还建行。不许因为一个可空关系对不上就整笔失败。
2. 一句新建、点一次确认：库里只能多这一行有变更的记录。空 patch 不得发牌，也不得进 jobs。
3. 写成功后左边现查确认不得再 aborted。无筛选整表不得当回执。

## 1. 口语外键

人话里每个要进库的值，按 schema 这一格：照写 / 枚举 / 指向另一行。不按字段名开特例，不单收人。

照写：确认面就是这句话，人可在表里改再确认。

枚举：只按 schema 选项。唯一则绑；0 或多则停，表上改。

指向另一行：先整列等值，再在目标 schema **有的列**上包含。只当唯一一行才收 id。0 或多都不猜。多条先选再继续，见 [业务记录五问 §12](records-panel-decisions.md)。

确认面：已绑显示解析后的那一行，不要还写口语装作绑好。未绑：提示这一格对不上，人在右边业务记录表改/选，再确认。可空可空着过；必填未绑则确认不能过。

禁止静默丢键还建行。禁止整笔因一个可空关系对不上就失败。

`$or` 只许目标 schema 上有的列。词表+图+schema。删除/过审找行失败仍是对不上行。

新建和改行的 patch 走这一格。入口键用 schema 标题和词表收成字段名（where 已有的那道），再按这一格绑值。回执里的说法不拿来当入口别名。删除和过审仍用这套收口找行，不往外键列写口语。图不参与收 id，target 以 schema 为准。

## 2. 空牌、空行

权威是人点的那一枚未使用、且有变更的牌。开口按 lines 全发是另一份写权，四种写都收成只发这一笔。

空 patch 只挡新建：不发牌。改行本来就拒绝空 patch。删除、过审没有字段 patch，这一笔动作就是变更，不拿空 patch 去挡。

开口里已经留下的空新建牌先作废，再写人点的那一枚。写成功后作废其余未用牌，只让它们不能再确认，这一步不再 POST。

## 3. leftover

权威是刚写下的身份。四种 wrote 共用。

回执现查必须带着这份 no 或 where。左边确认的是这张。无筛选列表不是回执：不拿它换左边，也不掐已经带上身份的回执。

round-end 继续停着。预览一成功不刷表。

## 你怎么验

契约已落地，机器测试过。下面三步还没手点，未手证。不 reload。

1. 新开会话。一句新建：每个要进库的值按 schema 这一格收。照写的，确认面就是这句话，表里改完再确认，库里是改后的值。枚举只按 schema 选项：唯一则确认面和库都是那个选项；0 或多则确认停，表上改完再过。指向另一行：目标 schema 上有的列先整列等值，再包含；唯一一行才收 id，确认面是解析后的那一行，库里外键是这个 id。0 行：确认面提示这一格对不上；可空可以空着确认，库里该外键空、其它字段仍在；必填则确认不能过，库里没有新行。多条不猜，先选再继续。不许静默丢掉关系键还建出外键空着的行。不许因为一个可空关系对不上就整笔失败。再改一行同一关系，同一条。删除或过审用口语当条件：对不上则原行还在，外键列不变。目标 schema 上没有的列不得出现在 `$or` 里。
2. 一句新建、点一次。库里只多一行有变更的记录。审计里 write 只有人点的那一枚，patch 非空。空 patch 不在令牌里，也不在 jobs。改行、删除、过审各点一次：write 的 id 就是点的那一枚，不是开口里每一行。
3. 写成功后左边现查带着刚写下的 no 或 where，这一轮不是 aborted。pending 不是无 where、无 no 的整表。预览刚成功时左边不刷。删除或过审再成功一次，左边同一条。
