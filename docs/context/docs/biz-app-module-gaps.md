# 业务应用模块现在没搞好的

依据：三 Tab 现网与闸（scene-39，`6dcee573`）、[业务应用模块收口](biz-app-module-plan.md)、[应用打开与能力](apps-open-and-capability.md)、规格 04 / 05、冻结四条契约、[增删改审手测集](biz-write-eval.md)、[业务数据评测](biz-data-eval.md)。2026-09-26 对过。点头之前不改。

业务应用就三页：**应用**、**业务记录**、**操作记录**。

## 先说清楚

**三页都没收口。** 能演示、多轮图过，没有一次按契约站住。

[业务应用模块收口](biz-app-module-plan.md) 写「业务记录 / 操作记录主线已图过，只差小尾巴」——**假。** 小尾巴在方案里是早报抽屉标题和探针字。记录没收口的是 kind 资格、pending 管子、右表权威、问卡、过审已是目标态、页脚对象集。操作记录页本身图过，顶栏代写仍绕过审计。

根因不是「还差几个按钮」：

1. **没有单一「这一句的结果」。** 应用 SQLite、连接器业务库、操作审计是三套真值。业务记录右表还听 SSE、BFF `lastEmitted`、官方回合表三路合并。
2. **应用壳能出 spec，不等于是产品。** 创建管道通了；铺面、能力、目录还是脚手架。
3. **闸会发牌，不等于过账能用。** 预览令牌多轮图过；人确认 → 写库 → 表和审计一致，没有按 W 集结案。
4. **方案自己报完成，以现网和契约为准。** AV「八项全过」后面 AW–AY 仍未齐；BQ 脚本绿过，协调器没对上屏。

## 业务记录

**整块没收口。** BA→BQ 十条活用例 × 四条契约，没有在同一会话、同一套人眼图里一次站住。同 SHA 重跑，第 1 条能从工单 21 抖成「客户 · 现查 · 0 行」。

| 契约 | 要求 | 现在 |
|---|---|---|
| 1 kind 必须连着业务表 | 图谱概念不得 preview | HTTP 能拒无表 kind；catalog 仍从 `skos:Concept` 出。决策 15 没收死 |
| 2 一句话一张 pending | 假 kind 第二枪不上屏 | BFF 仍 `lastEmitted` + 官方表 + SSE 合并。左 97 右报销单 0 的史还在 |
| 3 右表必须换上这一张 | 空表/取消不得倒目录、不得 hold 旧表 | BK 单场景图过；BG/BJ/BO 回潮。重开会话带上一句 kind 未收 |
| 4 模糊名先选 | 一批不一家家问 | BD 图过第 4 条；BE 第 2 条一批现查变成「哪一档」 |

还没搞好、且不是契约能概括的：

- **hop：** 闸能做 N-kind 交集；面板仍跟最后一次单侧 preview。整句路径靠模型纪律。「这一句的权威表」([hop 卡住](hop-sheet-stuck-plan.md)) 没有图过闭环。
- **页脚：** UI 能显示 `hitTotal`。缺 enum/关系时仍交表；自环 peer chip 页脚和库数不一致；大量「总数未知」。不是对象集。
- **问卡：** 改行预览已出，左栏 Ask 仍开、模型仍转。BQ 称清了，协调器没图审。
- **过审已是目标态：** 令牌在，抽屉「没有可展示的变更」。`alreadyAtTarget` 改了 speak，抽屉空变更仍算失败。
- **横幅：** 过审预览仍写「AI 刚查了」。
- **读路径计划：** [业务记录修复计划](records-close-fix-plan.md) 要的「一轮结束才交表、词表 enum 唯一来源」没按计划跑完。[和 Palantir 比](palantir-accuracy-gap.md) 六条读差距还在。

跨对象 hop 主路径（回款∩合同等）和 chip 分列，**单场景能用。** 不能用单场景推论整块收口。

## 增删改查审

写在业务记录里发生，但账要单独算。

| 类 | 能用到哪 | 没搞好 |
|---|---|---|
| **查** | 362 条结构化现查，闸和现网条数对齐。 | 自环 peer 页脚；「停用客户…未关工单」只在单测，小模型现网未按标准句过；Qwen 出表后空转（[慢能收什么](qwen-slow-runtime-plan.md) 待批）。 |
| **增** | 预览能出令牌；无工作台确认，闸拒写。无写动作 role 时收成现查。 | 右栏 `resolveConnectedKind` 空表；顶栏新建不稳；连弹确认 / 幽灵令牌；口语外键空 patch **未手证**；过账成功不拉官方表。 |
| **改 / 删** | 带单号的预览能绑一行；>100 行闸上拒批量。 | 左右令牌错位；`changes:[]` 仍蓝条；取消后历史重开（W24）；成功后右表仍是预览行；0 行假成功 **未手证**。 |
| **审** | 「都过一下」能走过审预览；「待审的费用报销」无写 role → 现查（land 打过一次，换核要复打）。 | 短名打空 kind；批量 >100 未手证；空变更仍发牌；过账后状态和右表不一致。 |

**总判：** 预览多数能到令牌。**人点右栏确认 → 库 → 表和审计一致** 这一整条，W1–W30b 没有在重载核心后整包标过。磁盘上三刀新建、lookup-key、原话定动作、确认投影，单测过，现网手验集中在确认和回读。

手册 / 知识库 / 流程：同一会话模型可以先读再调闸；**写闸不认规章。** 不是业务应用三页里的洞，也不是已经结合处理。

## 不要搞混的

- 图过某一截 ≠ 模块收口。
- 现查评测满 ≠ 写手测过。
- 过审预览有令牌 ≠ 过账后表对。
- 创建管道通 ≠ 应用是产品。
- 脚本绿 ≠ 人对上屏。

对照能用（各一句，防止把整页写成不能用）：

- 应用：描述能建成本地应用，数据进 SQLite，不进业务记录 kind chip。
- 记录：部分 hop 原句能出对的一行表；写预览能跟最新一跳（非空变更时）。
- 写闸：无确认拒写；无写 role 的「待审+型」默认现查。
- 操作记录：能搜、能翻页。

下一刀不在这篇里派。先认：记录的权威表、写的确认回读、应用的铺面，是三件不同的事，不要再收成「补小尾巴」。
