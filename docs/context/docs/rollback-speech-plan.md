# 回退按历史里的那一行找，不要拿「回退」两个字去查

对照 [回退为什么对不上「回退」](rollback-zero-root.md)、[为什么口语是固定的「回退」](rollback-speech-upstream.md)。点头之前不改。

回退要找的就是当时写下的那一行。权威是历史里的对象和行主键，见 [五问 §8](records-panel-decisions.md)。现查、改行、删除、过审、新建的回退共用。不写死客户、CUST2056。

「回退」这两个字还可以给审查原文当记号：见到它就知道这不是当时那句人话。但它不能再占「用户原话」那一格。占了，找行闸就会拿它去当名字。

## 收成什么样才算好

1. 点回退：按历史里的对象和行主键去源系统找同一条。对上 1 行再出确认。找不到就说这一行对不上，不要按名称包含「回退」去查。
2. 确认写回：用同一条主键写。0 行是失败。
3. 审查原文仍能认出「这不是当时那句人话」。记号另放，不进找行用的原话格。空着的原话格已经够让写回审计换回当时那句。

## 和现有功能

不改口语改行。真人口语改行仍走「原话里剩下的名字换单号」。回退不走这一支。

审查原文：空着的原话格已经当「不是当时那句」。写回审计见到空或「回退」都换回原句。空继续算同一件事。

同一刀要收的洞：

1. 老记录没有行主键：说这一行对不上。不拿「回退」去名称里撞，不猜一行。
2. 预览单若靠原话格显示「这是回退」：改成看历史动作。

## 不要第三套

不要另开一条只回退客户的口。不要特赦「回退」两个字让闸跳过。不要让记号和主键并排都能决定查哪一行。

改行闸继续管真的口语改行（「恒通」压过模型顺手填的号）。回退不是口语改行，不要再走「原话里剩下的名字换单号」。

## 你怎么验

点头改上之后。操作记录里点 CUST2056 那条改行回退：预览对上深圳恒通电子这一行，备注 `测试修改` → `active`。确认后库里备注回到 `active`。不要再报对不上「回退」。审查打开这条，不当「回退」是当时原文。
