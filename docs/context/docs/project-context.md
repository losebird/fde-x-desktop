## 产品定位
本机个人 AI Native 工作台。壳 = FDE-X（React/Vite + BFF `runtime/server.mjs`）；引擎 = DSH（AI）、lan-assist（IM / 业务过账）、semantic-os（记忆）；自有数据 = SQLite。

## Ace 的产品方向（2026-09-16）
1. 应用模块：用户用**创建应用**、走 `fde-app-builder` 用提示词生成和改自己想要的应用，用来补工作台不够的地方；自有数据跑在 SQLite 上。创建和改是同一条路（话 → builder → spec → 工作面），没有「能做就不能改」。**spec 是运行时契约，不是用来否定提示词的。** 用户让 builder 改什么，spec 就要写得下；写不下就扩 spec，禁止说「被固定 spec 限制所以不能改」。决策 3 只禁止为每个应用写一套独特代码，不是拿瘦 spec 卡死 builder。现网夹具是创建应用做的，不是写死在产品里的官方应用。
2. 业务记录：用户用 AI 操作业务系统时相关数据**自动浮现**，页面上可增删改查审。
3. 早报：可自定义区块与信息源，可接邮箱、新闻、业务系统未完成工作。
4. 模块互通，尤其复用记忆模块（semantic-os）的语义能力。
5. 多个模块可同时撕出为浮窗，像真实桌面。
6. 最终交付**单一安装包**，内置 DSH / semantic-os runtime / lan-assist；macOS / Linux / Windows 通用。

## 第一性原理（Ace 2026-09-18，每次都要遵守）
- 不要偷懒。不要硬编码（kind / 动作 / 字段 / 单号 / 路径 /「只 hop 一对」都不写死）。
- 性能要好，稳定性要强，必须可生产使用，功能必须真可用。
- 每次改代码都不得把已经能用的功能搞坏（决策 22）。
- 冗余和不用的**生产代码**要清掉（探针脚本仍等 Ace 说没用了再删，不进发布仓）。
