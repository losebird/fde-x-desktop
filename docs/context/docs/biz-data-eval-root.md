# 三条没过的原因

还是评测里那三句。计划先按词表认出对象，后面又离开了词表和图。

## 只说长名，短名仍成上游

「工单处理记录」整句对照词表时，只认出工单处理记录。长名把那几个字占住了，短名工单没有被认成另一个对象。

接下来选上游。图上有工单到工单处理记录，于是工单进入候选。这一步只拿「工单」再对一遍原句，不再和长名抢字，短名就落在长名里面。计划因此写成工单，再接到工单处理记录。

右边按这条上游滤处理记录：处理记录 800 条，其中 2 条对不上任何工单，剩下 798。

## 图上没有的边，仍然走出结果

「联系人的工单」。词表里两个对象都在，图上没有它们之间的边。

选上游时不单看图，还看连接器字段。工单上有指向联系人的字段，这一步就把联系人收成上游。原句里本来就有「联系人」，于是计划写成联系人，再接到工单。

右边用工单上的联系人编号去对全部联系人。工单 401 条，2 条没有联系人编号，剩下 399。

## 两个对象共有的枚举被丢掉，右边是 0

「草稿的采购订单和费用报销」。两个对象都在词表里，草稿各自落在自己的字段上：采购订单是订单状态，费用报销是状态。库里分别有 33 条和 42 条。

「草稿」在这句话里只出现一次，却对上两个不同的字段名。计划把这一次出现当成冲突，两个对象上的条件都不要，并标成筛选被拒。

现查见到这个标记就不再查业务库，直接交一张空表。命中总数写成 0。
