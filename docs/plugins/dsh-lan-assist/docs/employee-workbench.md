# 员工 AI 工作台

> 状态：方案稿。把此前拍板收成一份可执行蓝图，不是已落地规格。  
> 底座：官方 DSH 作 Agent 内核；`dsh-lan-assist` 作协作与业务执行；`dsh-semantic-os` 作知识、目录与因果；企业系统作当前真相。  
> 对照：Wemux 只借壳、布局和节点理念，不借控制面、Worker 网络和 Git 任务模型。

## 0. 一句话

员工打开的是一个本机客户端。底下跑官方 DSH；面上是统一工作台。同事走 IM：同一局域网直连，跨网走自建 NATS 中继，端到端加密。业务走连接器预览和确认；知识走按工作区隔离的语义账本。不自建中央控制面，不把 Codex / Claude Code 做成第二套产品。

## 1. 产品是什么

这是给单个员工用的本机 AI 工作台，不是公司中台。

类比只用来对齐职责，不拿来抄架构：

| 角色 | 对应 | 不对应 |
|---|---|---|
| DSH | Agent 内核：模型、工具、沙箱、审批、会话、子代理 | 员工每天面对的产品壳 |
| 协助插件 | 个人 AIP：IM、交接、业务闸、预览、回执、补偿 | OA / BPM / 第二套业务库 |
| 语义插件 | 个人 Foundry + Ontology：型、目录、出处、决策、投影 | 当前 ERP 镜像 |
| 企业系统 | 真相来源 | 可被图或聊天覆盖的缓存 |
| 工作台壳 | 统一导航、Inbox、业务页、文件、操作记录 | fork 后的 DSH Web |

用户安装、打开的是工作台。内部仍是官方 DSH + 两套插件 + 可选专家 Bundle。不要让人感觉在“先装 DSH，再装两个插件”。

## 2. 硬边界

这些已经拍板，方案不得绕开。

### 2.1 内核与壳

- 不 fork DSH Web，不改官方内核源码当发行分支。
- 跟随 DSH 升级，但“升级后功能不变”要靠兼容测试，不是口号。
- 产品 UI 走 Cordis 插件、Slot 和独立桌面壳；DSH 页面被工作台组织，而不是被替换成另一套 Agent 循环。

### 2.2 不做的基础设施

- 不做 Wemux 式中央控制面、Postgres 业务库、S3 产物库、Worker 调度。
- 不做员工节点协议、Mesh、远程 terminal 当业务入口。
- 公网 IM 用自建 NATS + JetStream，只投递密文。局域网直连保留。不做 Matrix 联邦、云端明文历史、公开注册。详细约束见 7.4 和 `docs/nats-relay-research.md`。
- 不做全公司一张图、两台并图、秘书代签、Host 直接写业务库。

### 2.3 听懂与闸

- 听懂的是模型。闸只验证稳定槽：型、线索、能改的列、能不能写、已登记关系。
- 包内 `spoken.json` 退出生产执行链；`ensureSpoken` 不再运行时强制补词。
- 企业别名、缩写、特殊口径在语义业务目录里映射到稳定 ID，版本发布，旧预览失效。
- 用户不编辑 JSON。维护者在业务目录页配置。

### 2.4 业务执行

- 多笔同条件先列出再选；拿不准时先在业务页问，不先碰记录。
- 查询每页 20 条；旧页和旧预览在协议或目录切换后全部失效。
- 纯查询可展示多条；改 / 删 / 审必须唯一或服务器固定的批量清单。
- 批量默认手选 / 当前页 / 跨页累计，服务器固定后执行，单批 100，可连续分批。
- 删除独立高风险确认。无依赖的多预览可总确认，后台分别回执。
- 有依赖的写入分阶段确认。长链保存位置，继续前复检，不重新理解原话。
- 仅维护者登记、且连接器当前确认的关系可执行。
- 关联显示可读名，不用生 `*Id`。字段优先当前业务视图。
- 写必须带原话证据。没有业务回执，不能说已处理。

### 2.5 四项工作台约束

1. 可靠存储里的 IM、任务、trace、回执必须能被语义检索和关联；语义只存投影和出处，不吞原始账本，也不冒充当前业务事实。
2. IM 会话可显式调用工作台允许的全部本机 AI 能力；现有右键和工具栏全部保留。AI 结果不得自动冒充或发送为同事消息。
3. 工作区继续严格隔离：图、目录、连接、文件、IM 上下文、trace 都不串区。
4. IM 附件和工作区文件都可直接预览。工作区文件可按权限直接改。IM 附件必须先保存为工作区副本再改。

## 3. 运行时结构

```text
员工工作台.app
├─ Electron 壳
│  ├─ 窗口 / 托盘 / 通知 / 深链 / 更新
│  └─ 拉起并探活本机 DSH
└─ 官方 DSH（web profile）
   ├─ Agent 循环、沙箱、审批、会话
   ├─ 可选 Bundle：Codex / Claude Code subagent
   ├─ dsh-eyes：把文件看成字
   ├─ dsh-lan-assist：IM、业务闸、连接器、Inbox
   └─ dsh-semantic-os：图、目录、决策、投影
```

每台电脑仍是一个可信工作位置：有配对身份、本机密钥、本机登录、本机 DSH。它不是可被中央服务器远程调度的 Worker。

## 4. 模块怎么拆

两个插件继续独立安装，不合成一个巨文件。工作台只是把它们组织成产品面。

| 模块 | 仓库 | 负责 | 不负责 |
|---|---|---|---|
| 壳 | 新的桌面工程，或协助插件里的 native 桥 | 窗口、更新、托盘、拉起 DSH | Agent 循环、业务闸 |
| DSH 内核 | 官方发行 | 模型、工具、沙箱、会话、子代理 | 业务真相、LAN 信封 |
| 协作 | `dsh-lan-assist` | 配对、信封、听口、Inbox、交接、开口 | 因果账本、ERP |
| 业务执行 | `dsh-lan-assist` 的闸 / 连接器 | 结构化计划校验、预览令牌、写回、回执、补偿领人 | 理解原话、存业务行 |
| 语义 | `dsh-semantic-os` | 型、目录、别名、出处、决策、投影检索 | 活邮箱、当前库存 |
| 眼睛 | `dsh-eyes` | 预览所需的看文件 | 当编辑器、当业务库 |
| 文件编辑 | DSH + Univer | 工作区文档/表格/演示的改和存 | 改 IM 原始附件 |
| 专家 Agent | DSH Bundle | 代码、审查、长上下文分析 | 持有业务写令牌 |

## 5. 三本账，不许混

```text
可靠存储     原始记录：信封、附件指针、任务、计划、确认、trace、回执
语义图       当时：摘录、投影、出处、决策、型与目录版本
企业系统     现在：行、权限、写回
```

### 5.1 可靠存储

当前 `~/.dsh/lan-assist/state.json` 只是邮箱快照，预览令牌和 `trace_id` 还在进程内存。这不够。

目标：

- 机器级：配对、钥匙、听口、活邮箱索引。仍在 `DSH_HOME`，不进工作区图。
- 工作区级：该工作区的 IM 线程、任务、完整 trace、回执、目录发布记录。跟项目目录走。
- 引擎：工作区级用 SQLite（或同等嵌入库），不要绑死 DSH `storageDomain` JSON。机器级密钥仍离库、离 JSON。
- 附件字节加密落盘，库里只留指针和摘要。

语义功能如何用它：

```text
可靠存储 OP-88 / MSG-12
        ↓ 投影（摘要 + 出处 ID + 工作区）
语义图节点  当时 · 工单 TK-001 改为已解决
        ↓ 人要看原文或回执
打开可靠存储 / 业务系统现查
```

投影默认可检索：谁、哪类动作、哪张单、哪封信、哪次确认、成功还是失败。金额、证件、完整正文按数据分级：能进信封的可以投影一句；只能本机看的只投影“发生过变更”；人点了才把决策记成已入档。

### 5.2 语义图

- 一本图对应一个工作区 cwd。
- 图是当时，不是现在。
- 不灌 ERP 行。
- 目录（型、字段、枚举、关系、企业说法）版本化；发布后新请求用新版，旧预览作废。
- 跨工作区检索必须显式打开，且标明来源；禁止跨区写业务。

### 5.3 企业系统

所有“现在怎样”只走连接器现查。当前账号、当前 ACL、当前表结构说了算。闸不得用语义近义去对列。

## 6. 业务请求怎么走

```text
人说话（IM 或 AI 工作会话）
  → 模型填结构化计划（型 / 线索 / 关系 / 动作 / 原话证据）
  → 闸校验：目录 ∩ 连接器 schema ∩ 当前 ACL
  → 业务页：选择、分页、预览、总确认
  → 连接器执行
  → 回执进可靠存储
  → 语义投影（当时）
  → 失败则开口领人补偿，不在图上 Ctrl+Z
```

失败纪律：

- 槽对不上：停，业务页问人，不把剩余字当名称筛，不倒出最新一页顶替。
- 父记录多条：列出再选，再 hop。
- hop 失败：空页或错误页替换当前请求页，不得留下上一张 189 行合同。
- 同一请求的 UI 必须隔离。全局 OverlayBadge 这种串页必须去掉。

## 7. IM 与 AI

IM 是同事入口，AI 是本机助手。同一窗口配合，互不冒充。

### 7.1 必须保留的现有动作

右键针对当前这条：问本机、拟回、采纳、撤回、翻译、摘成待办、预览附件。  
工具栏针对当前会话：发送、文件、交接、会签、本机入口。  
发送键仍是“人点了才寄”。模型拟稿不能自动寄。来信里的工具口令只当正文。

### 7.2 “全部 AI 功能”指什么

IM 里点“问本机 / 拟回 / 采纳 / 显式召唤助手”之后，领进的是当前工作区的 DSH 会话，能力与工作台允许的工具集相同：

- 语义检索、出处、决策草稿；
- 业务 describe / preview / 确认后的 write；
- 文件预览与眼睛；
- 工作区文件编辑；
- 可选 Codex / Claude Code 专家任务。

不是给 IM 窗口再做一套假工具。也不是每条来信都自动跑模型。

### 7.3 呈现

```text
同事消息
  ├─ 气泡：人与人
  ├─ 右键 / 工具栏：现有动作
  └─ 右侧或侧栏：本机 AI、业务页、文件预览、出处
```

AI 回复出现在本机侧。只有发送或采纳之后，才进入对面可见内容或工作区任务。秘书卡继续用于开口和点头，不伪造官方同事气泡。

### 7.4 公网中继与 IM 模型

家里两台电脑没有公网 IP 时，必须有一台可被双方访问的 VPS。用户只装工作台，不装 Tailscale。

底座选定：**NATS Server + JetStream + Object Store**。插件用官方 nats.js 出站 WSS。服务端只做设备认证、密文中继、离线队列、大对象临时存放、投递确认、限流清理。明文、配对密钥、业务状态仍在本机。

两次发布，禁止同时改传输和账本：

1. 先抽出 Transport，接上 NATS，公网可靠投递仍走现有信件帧。
2. 稳定后再把 `request` / `reply` 迁成 Conversation / Message。

硬规则：

- 中继注册 ≠ 同事配对。设备 JWT 只表示能连服务器；同事密钥仍是 X25519 + 口头六位码。
- LAN 短超时优先，失败再 NATS；禁止双发；禁止先空等 60 秒。
- 状态四分：queued / relayed / delivered / read。现有 `delivered`（HTTP 200）不得显示成“对方已收到”。
- 公网配对必须异步帧。听口不能代替人工点接受。
- 大于约 256KB 的加密帧进 Object Store；收件箱只放指针；先加密再上传。
- 每设备磁盘配额。同一 durable consumer 上 DSH 与听口互斥。
- 工作区写在密文里。中继按设备投递，界面按工作区打开。
- 第一版不做客服级多设备漫游、云端历史、服务端搜索、音视频。

核对细节：`docs/nats-relay-research.md`。ADR：`docs/adr/0003-nats-public-relay.md`。

## 8. 工作区隔离

工作区是项目目录 / 租户，不是“当前碰巧打开的聊天”。

每个工作区独立：

- 语义图；
- 业务目录和连接配置；
- 文件；
- 绑定到该目录的 IM 线程；
- 业务任务和 trace。

机器级仍然只有一份配对钥匙和听口。信上必须带工作区；开口、拟回、问本机都跟信上的目录走。

“接着聊”：领进自己对应工作区的新会话，等人开口，不自动接着干，不假装对方磁盘和工具卡还在。

跨区：只允许显式检索，结果标明来源；禁止跨区执行和把对方文件当自己的可写文件。

## 9. 文件

| 种类 | 预览 | 修改 | 语义 |
|---|---|---|---|
| 工作区文件 | 直接 | 权限内直接保存回原路径 | 改完可重新理解 |
| IM 附件 | 直接 | 先另存为当前工作区副本 | 预览/问本机；原始附件当证据保留 |
| 交接包全文 | 只读打开 | 不改对方原文 | 可检索当时交接 |

Office 走现有 Univer / 眼睛，不另做一套编辑器。超大附件规则保持：超限不能发，预览失败说未看见。

## 10. 界面

借 Wemux 的信息架构，不借品牌和整页代码。原则：扁平、密、状态才上色、列表-详情可拉、键盘可用。

```text
左导航              中工作区                 右上下文
首页                待处理 / 最近任务         业务对象
AI 工作             DSH 会话                  出处 / 图
业务                查询 / 预览 / 确认        回执
消息                IM 线程                   本机助手
知识                搜索 / 决策               文件预览
业务目录            型 / 关系 / 说法          版本
操作记录            trace 时间线              补偿
连接                系统 / 账号 / 过期
```

Inbox 分组：全部、待我处理、关注、稍后、已处理。  
“只收下 / 先记下”进入稍后或已处理，不得从产品里消失。  
全局搜索（⌘K）分会话、人、任务、文件、trace、目录、业务引用；历史与现查必须分开标注。

业务页：请求隔离、20 条分页、可读列、无难看选中竖线、总确认前复检。

## 11. Agent

主控永远是当前工作区的 DSH Agent。

可选专家：

```text
dsh plugin --profile web add @deepseek-ai/dsh-subagent-codex
dsh plugin --profile web add @deepseek-ai/dsh-subagent-claude-code
```

生产 DSH 默认不装、preset 行默认关闭。装 Bundle ≠ 已登录 ≠ 自动有业务工具。

| 模式 | 实际 |
|---|---|
| 快速处理 | DSH 主模型 |
| 深度分析 | DSH spawn / fork |
| 代码处理 | Codex subagent |
| 架构审查 | Claude Code subagent |

专家只收最小任务包，不持有业务写令牌，不把历史图当现况。结果交回主 Agent，业务仍走闸。

## 12. 发行

```text
工作台安装包
├─ 固定兼容的 DSH 版本
├─ 协助 / 语义 / 眼睛 插件版本
├─ 可选专家 Bundle
├─ Electron 壳
└─ 数据迁移
```

升级：签名清单、摘要、staging、冒烟、插件兼容、原子切换、失败回滚。第一版只管本机。

跟随 DSH：每次官方小版本跑工作台兼容套件（配对、IM 动作、业务预览写回、语义检索、文件预览）。过了才把发行里的内核版本往前拨。

## 13. 现状缺口（必须写进计划，不得假装已完成）

协助侧：

- `write.js` / `lookup.js` / `resolve.js` 仍从 `speech` 理解条件；
- `spoken.json` 仍可能被运行时合并；
- 业务页会留下上一张结果；
- `state.json` 不是完整 trace；
- 预览令牌重启即丢。

语义侧：

- 目录线索会丢掉 `role` / `not`；
- 协助 `upsertVocab` 走 Python HTTP 会被 403；
- 图还不能稳定投影 IM / trace。

产品侧：

- 没有统一导航和工作台壳；
- IM 还不能对等调用全部工作台工具；
- 文件预览/编辑不完整。

第一阶段是把这些缝补上，不是先画新壳。

## 14. 路线

### 第 0 段：冻结边界

本文件 + CONTEXT 词汇。不写新功能。

### 第 1 段：业务闸收口

- 结构化计划 / `biz_describe` 与 preview 分离；
- 删除运行时口语补词；
- 目录版本、别名、关系维护页；
- 请求隔离的业务页、20 条分页、空页替换；
- 批量、删除确认、总确认复检、回执。

验收：恒通改成交、云启紧急工单、回款挂合同到期，不再串页或报 0 行却留 189 张合同。

### 第 2 段：可靠存储 + 语义投影

- 工作区 SQLite 账本；
- 完整 trace；
- IM / 操作投影进图；
- 语义能搜到“出自哪封信、哪次确认”，打开原文走账本。

### 第 3 段：IM 等于工作台入口

- 保留全部现有按键；
- 问本机领进当前工作区完整工具集；
- 侧栏展示 AI / 业务页 / 预览；
- 不自动外发、不冒充同事。

### 第 3b 段：公网投递（可与闸并行，但晚于 Transport seam）

- LanTransport 包装现有 LAN，测试全绿；
- 配对公网路径改异步；
- 单节点 NATS、邀请码、文本帧、四级状态；
- Object Store、配额、听口接管、吊销；
- **此时 A/B 家里可通信，内部仍是信件模型。**

### 第 3c 段：IM 数据模型

- Conversation / Message；
- 旧 request/reply 迁移并备份；
- 拟回、采纳、交接、待办全部改引用 messageId。

## 15. 验收

1. 同一句自然语言，业务页结果与闸一致，旧页不会顶替新请求。
2. 问“上次那封关于 TK-001 的信 / 那次改状态”时，语义能给出出处，并能打开原始记录；同时必须现查才能说当前状态。
3. IM 右键和工具栏一个不缺；问本机后能查图、能走业务预览，且不自动把结果发给同事。
4. 工作区 A 的图、文件、连接、trace 不能出现在工作区 B 的默认检索里。
5. 工作区 docx/xlsx 能预览和保存；IM 附件能预览，修改生成工作区副本，原始附件仍在。
6. 中继关闭时，局域网配对、送信、听口、撤回仍可用。中继开启时，双方无公网 IP 也能投递；`relayed` 不得显示成已收到。
