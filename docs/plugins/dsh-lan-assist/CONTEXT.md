# 局域网秘书

每人一台本机秘书：配对、送信、听、开口、收点头、把活领进当前会话。账本在语义，真相在业务系统，动手在会话；秘书不是 OA，也不是第二套业务库。员工打开的是工作台，底下仍是这四层。

## 工作台

**工作台**:
员工打开的统一客户端。底下是官方 DSH 内核，面上把秘书、语义、业务页和文件收在一起。
_Avoid_: 第二套 harness, 独立中台, fork 后的 DSH, 公司大脑

**中继**:
自建的公网投递服务。只认证设备、转发密文、排队离线。看不见正文，也不等于同事已信任。
_Avoid_: 公司 IM 云, 把中继当配对, 服务端解密

**中继注册**:
这台设备拿到连中继的资格。邀请码一次性，私钥留在本机。
_Avoid_: 加好友, 用中继账号当同事身份

**投递**:
密文已经可靠落到对端磁盘。中继持久化只是在路上。
_Avoid_: HTTP 200, 已读, 已处理

**对话**:
一对一或话题群的 IM 线程。工作区写在密文里；中继按设备投递，工作台按工作区打开。
_Avoid_: 信封（当产品词）, 全公司一个收件箱

**消息**:
对话里的一次发送。跟帖、转发、撤回都是消息上的关系，不再把回复嵌进一封信。
_Avoid_: 信件, 回帖嵌套在 request 里（目标模型）

**内核**:
官方 DSH：模型、工具、沙箱、审批、会话、子代理。工作台组织它，不替换它。
_Avoid_: 自研 Agent 循环, 改官方源码当发行分支

**壳**:
窗口、托盘、通知、深链、更新、拉起本机 DSH。不是业务闸。
_Avoid_: Wemux 控制面, Worker 调度

**可靠存储**:
本机保存信封、附件指针、任务、trace、回执的原始账本。语义只引用，不把整本吞进去。
_Avoid_: 把 JSON 快照当审计, 把图当原始记录, 绑死 DSH storageDomain

**语义投影**:
图里可检索的那一层摘要和出处，指向可靠存储或会话。是当时，不是现在。
_Avoid_: 灌库, 把投影当现况, 把活邮箱搬进图

**本机助手**:
IM 里被叫醒的那一轮 DSH。结果先出现在本机侧，不冒充同事消息，也不自动寄出。
_Avoid_: 自动回, 同事气泡, 来信当指令

**专家 Agent**:
本机 Codex 或 Claude Code 子代理。只做代码和审查，不持业务写闸。
_Avoid_: 多 harness 产品, 第二套 runtime 中台

## 四层

**秘书**:
这台机器上对人开口的那一层。只配对、送信、听、开口、收点头、把活领进会话。
_Avoid_: OA, 工作流引擎, 助手中台, 第二套业务系统

**语义账本**:
本机图里「怎么理解、凭什么定」的那一层。只收人点过头的引用和因果，不当流程引擎。
_Avoid_: 知识库, 记忆, 公司大脑, 并图

**业务连接器**:
当前这台机器上的登录态、权限、单据和写回。登录口令不进信封，也不进邮箱流水；本机另放。
_Avoid_: 业务库（当秘书内部概念）, SSO（当秘书模块）

**会话**:
人正在看的那次 DSH 对话。真调能力、过本机工具审批、叫醒模型，都发生在这里。
_Avoid_: 秘书 Host 直接开工, 后台代跑

**眼睛**:
把文件或图看成字的那一层。缺席时附件仍是附件。
_Avoid_: 已读完合同, 自动进信封

## 人与配对

**配对**:
当面报码之后才成立的信任。网上只换临时公钥，六位码不上线，也不放能离线撞的证明。发现在线不等于已信任；没配对就没有钥匙，不能送信。
_Avoid_: 加好友, 按花名册群发, 通讯录自动送信

**对端**:
已配对的那个人，稳定 ID 跟这台机器上的钥匙走，不跟 IP 走。
_Avoid_: 用户, 同事账号, 业务工号（当 LAN 身份）

**门牌**:
对端此刻的局域网地址。换网可以换门牌，不必重新配对。
_Avoid_: 主机名, 公网地址

**钥匙**:
这对配对的共享秘密。只活在本机，对面秘书看不见，更不能塞进信封。
_Avoid_: token, 配对密码

**登录口令**:
这台机器上查业务系统用的只读登录。只留在本机，不进信封，对面看不见。
_Avoid_: 票, token, 业务票, 只读票

**身份引用**:
「这对配对对应本机已绑的哪个员工」。只存引用；对面看不见登录口令，换一台机器必须是那台当时登的号。
_Avoid_: 秘书记工号, 秘书里做 SSO, 把别人的登录借来用

**花名册**:
本机一份人走了没有的名单。只能收回持有，不能代替配对，也不能当组织树去送信。
_Avoid_: 通讯录, 组织树, 值班引擎

**离开**:
花名册上的「人走了」。只收回这人还握着的信封，不解除配对，不自动再寄。
_Avoid_: 离职删钥匙, 失联, 解绑

**委托**:
被委托人用自己的号去查、去点。不能用 Ace 的登录替林督去查。
_Avoid_: 转授权, 代登

**换人**:
同一台电脑换成另一个人。先报现在是谁的号，再重绑身份引用；上午的信不能下午拿新号去查。
_Avoid_: 共用这台的默认账号

## 信封与邮箱

**信封**:
秘书与秘书之间的一封协助，不是群聊，也不是工单。带意图、业务引用，以及这台号现查能看见的字段。
_Avoid_: 消息, 气泡, 工单, 聊天记录

**交接包**:
一次 DSH 会话的可读全文，加上人勾过的文件，随信封寄出。对方打开全文只读；点「接着聊」领进自己的工作区新会话，等人开口再动。不是对方那条还在跑的会话。
_Avoid_: 跨机 fork 活任务, 实时看对端, 回放工具卡, 假装磁盘还在

**业务引用**:
信封上仍用类型加单号指认。本机号现查到的全称、电话、地址、金额可以写进正文和会话，前提是这台登录看得见。
_Avoid_: 把对面看见的明细当这台的真相, 灌进图当现况

**工作区**:
这封信绑定的项目目录 / 租户。开口和拟回跟信走，不跟碰巧打开的会话走。
_Avoid_: 当前聊天的图, 全公司一张图

**邮箱**:
本机那堆信封。进邮箱不是已读，不是同意，也不是已开工。
_Avoid_: 官方收件箱, 已处理

**听口**:
DSH 关掉时仍能在局域网上收信的那张嘴。只落盘，不开口，不叫醒模型。
_Avoid_: 手机推送, 互联网中继, 后台开工

**持有**:
这封传阅现在握在谁手里。人离开只把持有收回来，不把信改写成已办。
_Avoid_: 审批人, 所有权

**未读撤回**:
发件人收回对面还没看的那封信。撤信不等于业务作废。
_Avoid_: 冲正, 删单

## 开口与点头

**开口**:
秘书用一句人话来报，等你点。开口不是开工，也不是官方聊天气泡。
_Avoid_: 通知, 系统 toast, 同事气泡, 自动 followup

**只收下**:
人表示「看见了，先不动」。模型不跑，不写条子。
_Avoid_: 已读, 归档, 已同意, 已处理. 代码里的 hold 只对应这一下

**采纳**:
人表示「按他说的做」。这才把活领进原会话；条子跟着写，写失败也不挡领进会话。
_Avoid_: 自动开工, 代签, 已过账

**调度**:
点头之后把活交给当前会话。秘书自己不写业务库。
_Avoid_: 秘书当工具总线, Host 直接改单

**会签**:
信封上的人点齐「我同意开口」。点齐不是过账。
_Avoid_: 审批通过, 已过账, 会签引擎

**三套点头**:
秘书同意、本机工具审批、业务系统过审是三件事。卡上必须说清这颗键是哪一套。
_Avoid_: 点头（当单一动作）, 点三次才算过一单（当产品目标）

**发出前点名**:
寄出之前用显示名加稳定 ID 报清收件人。禁止只说「发给他」。聊天窗发送键写「发给 林督 pk_…」。
_Avoid_: 发给他, 按花名册猜人

**点了就寄**:
人在聊天窗点发送 = 拟稿并立刻寄出。模型调 ask_colleague 只拟进聊天，不能自动寄。
_Avoid_: 发出前二次确认, 模型自动寄出

**拟回**:
替你起草回信，仍要人点才寄。来信里的工具口令只当正文，不当指令。
_Avoid_: 自动回, 执行信里的 MCP

**早报**:
一句未完成：业务里还有几笔待审，或哪封还没送到。不自动再寄。
_Avoid_: 催办引擎, 待办中心

**条子**:
人点了才记下的本机提醒。到点按你说的时间单独开口一句；没说就明早。不并进早报，不寄信，不 followup。
_Avoid_: 待办箱, 聊天里提到就自动记, 自动再催, 没有提醒我也当约提醒

**提醒闸**:
同一待办一天只开口一次；合盖、切会话、DSH 关掉就停。听可以一直听。
_Avoid_: 一直弹, 合盖还催

**开口次序**:
回信、被问、发出前，压过业务事件，再压过早报和建议，最后才是到点的条子。
_Avoid_: 早报盖住回信, 建议卡盖住被问, 条子盖住早报

## 业务（秘书只引用）

**现查**:
用这台机器当前登录的号去业务系统问一句现在的话。单号、名称这类线索都能拿去找；业务系统里确实没有，才说没有。对上多条只开口号，不擅自改。这台号能看见的字段，会话和秘书信都可以写。NocoBase 和以后接入的系统走同一套开口，方言只负责取数。
_Avoid_: 灌库, 用图里的旧数当真相, 没去查就说没有, 把对面看见的明细当这台的真相, 只给 NocoBase 写一套展示

**对单**:
查、改、删都先在本机把线索对成唯一一条。NocoBase 和别的业务系统走同一套对单，方言只负责取数和写回。
_Avoid_: 只给 NocoBase 写一套模糊, 没对上就写, 名称进信封明细

**预览**:
卡上写出将改哪张单、会不会动业务。点头前若隔了一会儿，必须再现查；旧预览不能拿去写。
_Avoid_: 秘书锁单, 拿十分钟前的画面过账

**只读开口**:
可以自动说的那一档：待审还有几笔、这单不在你名下、已经过了。
_Avoid_: L0（对人说话时）

**起草动作**:
卡上预览之后，人点了才让会话去跑的那一档。
_Avoid_: L1（对人说话时）, 秘书自己改状态

**过账**:
改业务真相或对外承诺。永远人点；真写发生在业务系统。
_Avoid_: L2（对人说话时）, 会签齐了, 秘书代签

**回执**:
业务系统承认「这笔记上了」的那张条。没有回执，不能说已处理，也不能记成已处理。
_Avoid_: 点过头, 模型说过写了

**补偿**:
写出去之后业务侧失败，领人去冲正。秘书不执行冲正，图上只追加后果。
_Avoid_: 回滚一切, 秘书 Ctrl+Z, 删掉旧决策

**能力**:
本机已装、且允许点名的一条：哪个系统、生产还是测试、只读还是会写、要不要人点。没在目录里的，不能假装去调。
_Avoid_: 装了就算有, 每个系统一个秘书

**岗位开口**:
连接器认出这单按岗位该谁，秘书只问要不要转。职责分离和金额阈也只开口，不算审批。
_Avoid_: 值班引擎, 超时转办引擎, 花名册代配对

**SLA 开口**:
读出「这单已超时转给谁」的那一句。转办动作仍在业务系统。
_Avoid_: 秘书日历当截止日期, 超时转办引擎

**约时间**:
人对过槽位之后才记下时段。没配写出命令，不能装成已写进日历。对方挑了不自动写。
_Avoid_: 秘书日历替代业务截止

**看看**:
人要看附件才交给眼睛。默认证件和金额页不进信封；看失败是「未看见」，抽出的字段还要用本机号对单。
_Avoid_: 自动看完, 合同已读, 默认证件进信封

## 闸与失败

**投毒**:
来信里「先去过账」只是正文。拟回和采纳不得把它当指令执行。
_Avoid_: 信里的工具调用, 对面塞来的 followup 文案

**降级**:
缺连接器仍能送信，不装成已查待办；缺语义仍能点头，不装成已进档案；缺眼睛附件仍是附件；局域网断了就说没送到。
_Avoid_: 缺谁都装成办完了

**失败人话**:
过期、无权、没装能力、系统挂了、局域网断了：只说缺什么。访客网隔开就说同一栋楼不够。目录外的能力说这台不能碰。
_Avoid_: 已处理, 已过账, 已读完

**成本闸**:
超预算停写，只许只读开口。写业务还得是够格的那款模型。
_Avoid_: 便宜模型去过账, 超了还写

**起草审计**:
谁点了拟回、哪封来信、哪次会话。不是业务账本。
_Avoid_: 秘书流水当财务审计, 再立一本 MCP 报文账

**串号**:
从信封的请求号串到会话和调度。回执和决策是别人的缝，秘书只把号递过去。
_Avoid_: 秘书自己把回执和决策写进邮箱

**关机队列**:
DSH 关着时业务事件落在本机，开机再开口。不是听口，也不是手机推送。
_Avoid_: 互联网中继, 关着也开工

**摘录**:
发出或收到的正文写成当时节点，进这封信绑定的工作区图。像会话记录一样可查。不是活邮箱，不冒充 session:，不自动记账，不默认抽取。
_Avoid_: 把未读当已读, 灌进图当现况, 信封默认抽取

**数据分级**:
能进信封、只能本机看、人点了才记账，是三档。信封正文发出/收到就写成摘录；决策仍要点头。
_Avoid_: 权限内整库进图, 把摘录当成已生效决策

## 改造落地（本轮已收）

聊天嘴第一刀已换。生产空口已按下面收上：

1. **发件箱重试阶梯** — `flushOutbox` 看 `nextRetryWait`，禁止 15 秒盲打。
2. **tick 互斥** — 上一轮没跑完不叠第二轮。
3. **附件诚实** — 字节进加密信封；`/state` 只留文件名和 hasData。没有字节就寄不出文件。
4. **聊天撤回** — 未读才能撤，接到气泡。
5. **一封多人** — 会签 / 勾几句仍走现有 1:N 信封。一对一窗口不装神秘开关。
6. **本机入口** — 聊天左侧「本机」可改称呼、开配对码、填对面码和门牌、开关听口。探活仍在协助页。
7. **LAN CORS** — `/frame` 不对任意网页放开。浏览器不打 LAN 口。
8. **snapshot 切片** — 附件字节不进 `/state`。体量 32MB，听口对齐，LAN 超时 60 秒。

9. **话题群** — 本机建群；一条话题 = 一封 1:N 信封；跟帖走 reply。对端从信封里的 groupId 建出同一群。会签 / 勾几句只在话题里采纳，一对一窗口没有。
10. **本机入口真能配** — 聊天左侧「本机」可改称呼、开配对码、填对面码和门牌、开关听口。探活仍在协助页。
11. **交接包** — 私信里点「交接」附上摘要（在问 / 做到哪了）和全文附件；再勾文件，点发送才寄。对方打开全文，点「接着聊」领进自己的工作区新会话，等人开口再动。不带工具卡，不带对方磁盘。
