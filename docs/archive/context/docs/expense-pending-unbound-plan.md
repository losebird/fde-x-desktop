# 现查 where 按格子收，不要外键一支拍板

对照 [为什么现查条件只剩外键 id](expense-pending-unbound-upstream.md)。点头之前不改。

写入已经按格子分成照写、枚举、指向另一行。现查、改行、删除、过审找行共用这一套。词表 + 图 + schema。不写死费用报销、待审、问题描述。

外键收口那件别的事还在：口语名字收成 id。留下当投影，不整段删。能单独否决「这句话的现查」的那截（没 id 就整段不要、重写全部 terms）清掉。

## 收成什么样才算好

现查名单谁留下，按这一格：

- **照写 / 文本列：** 点了列名就留下，去这一格的现网值里比。
- **枚举：** 已对上 schema 选项就留下。
- **指向另一行：** 才走外键收口。收到 id 才当已绑；没收到就这一格未绑，其它格不动。

`WHERE_UNBOUND` 只认「列名没对上」。已经成形的枚举或文本列，不得再被外键规则当成没对上列名。

## 不要第三套

不要另写一套「待审特赦」。不要在 lookup 里把空名单再猜回去。不要让槽、按列去比、外键收口并排都能单独留下或否决 where。

空失败换不换上一张表，仍跟列有没有成形走，不另开一条报销专用闸。

## 你怎么验

点头改上之后。新开会话：

1. 「待审的费用报销」：打到 `biz_expenses:list`，`status=待审`，右边是这 97 行，不是上一张工单。
2. 用问题描述删那笔：where 是 `description` 加那句，不是 `WHERE_UNBOUND`，也不报对不上「胡文」。
3. 「恒通的工单」这类口语外键：仍收成客户 id。外键没对上：这一格未绑，不得倒成无筛选整表。
