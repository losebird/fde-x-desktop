# 按列去库里匹配：怎么收

对照 [按问题描述删为什么对不上](delete-by-description-miss.md)。点头之前不改。

词表 + 图只描述结构：有哪些列、哪些边。不抄业务表里的行。现查、改行、删除、过审找行共用。不写死工单、问题描述。

## 两步，不要第三套条件

1. **对上哪一列。** 人话里的列名，对 schema 标题或字段名。词表有更好；词表没有、schema 有标题，也算对上。对不上列，不要猜。
2. **去这一列的现网值里比。** 人要找的那截字，和业务表这一格里已经有的值比：先等值，再包含。比的是库，不是词表，不是枚举命中表。

不要再把人话原文当成一条要过 `modelWhereAgreed` 的条件。那一闸只该管枚举。文本列对上之后，直接查这一列。

不要因为原文里有「客户」「故障」就跳到客户，或改成只留类型/优先级。人没说从那一型出发，图的边不自动走。

## 收成什么样才算好

「问题描述是这段字，删那一行」：认出问题描述这一列，去工单表这一格的值里找。对上 1 行出删除预览；多行先选；0 行说这一列对不上，不要拿上一张单顶上。词表仍然没有这句描述，也不该有。

## 和旧规则

不打架的：

- 词表+图只描述结构，不抄行（[五问](records-panel-decisions.md) §10）。
- 对上多行先选再继续（§12）。不默默挑一行，不倒成全表。
- 枚举仍只认 schema 选项。指向另一行仍要唯一 id。
- 不从人话发明列：人没点出列名、schema 也对不上，就不要猜一列去扫。

要改范围的只有这一条：`modelWhereAgreed` 现在对所有 where 都要求值是枚举命中。文本列对上之后，这条不该再挡。枚举列继续挡。

会引出新洞、必须写进同一刀的：

1. 描述原文里的「故障」「紧急」「客户」不能再收成类型/优先级/跳边，和这一列的库比叠在一起。人点的是问题描述，就只比这一格。
2. 包含会变宽。对上多行走 §12，禁止当全表删除。
3. 列名对不上时，禁止拿剩下的「胡文」去扫客户名称。

## 你怎么验

点头改上之后。新开会话，用描述删那笔：预览对上库里这一列包含这段字的行。不要再报对不上「胡文」。词表里不会多出这句描述。
