# 原话定动作：待审的费用报销应走现查

对照：[待审为什么变成过审](qwen-pending-as-approve.md)、[小模型怎么才能精准操作业务数据](small-model-biz-ops-plan.md)、决策 15 / 22。

点头之前不改。

## 标准

人说「待审的费用报销」，没有「过了 / 批准 / 都过一下」这类写动作，就只**现查**待审表，不发过审令牌。人说「把待审费用报销过了」，才过审预览。

不写死待审、费用报销、过审。动作和状态都从词表 `can` + 动作 role + 字段枚举来。模型填的 `action` 只是线索，**原话 + 词表是权威**。

## 不是只改词表

过审动作 role 已经在。缺的是闸的缺省，不是再加一行「待审的费用报销 = 现查」。把状态字写进过审 say 会更糟；把整句写进现查 say 是特赦，会和「都过一下」抢。现查 say 可以补「有哪些 / 列出 / 看看」这类问句动词，补不全「待审的 X」这种没有动词的句子。没有写动作 role → 现查，这是闸的规则，词表加不出一个「空」。

## 现在差在哪

`recoverWriteIntent` 已经能：口语命中写动作 role 且 `can` 有该动作 → 覆盖成过审；口语是「现查/列出」且无写动作 → 把错填的写动作拉回现查。

「待审的费用报销」两边都不响：没有写动作 say，也没有「列出」二字。Qwen 填了过审，闸照做。词表里「待审」是 status 枚举，不是过审 say——闸没教错，是**缺省把动作槽交给模型**。

## 收成什么样

同一套格子，词表 + schema：

1. **口语命中唯一写动作 role**（过审 / 改行 / 删除 / 新建）且该型 `can` 有 → 就是这个写动作。
2. **没有写动作 role**：型 + 条件（含状态枚举）→ **现查**。模型填的过审/改/删不得留下。
3. **又像看又像写**（写动作 say 和「列出」同时有，或 0 个写动作却模型坚持写、口语对不上）→ 现查先出表，回执问这一格：看还是过审。不静默发票。
4. 枚举字（待审、停用）只当筛选，不当动作。

`spokenListAction` 不要只认「现查/列出」几个字。没有写动作 role 的型+条件，就是现查。不要第三套「待审特赦」。

## 不要做

- 不教 Qwen prompt「待审=现查」。
- 不把「待审」写进过审 say。
- 不取消人明确要过审的路径。
- 不自动 `biz_write`。

## 你怎么验

Qwen 新会话：

1. 「待审的费用报销」→ `action=现查`，待审表，无 `preview_id`。
2. 「把待审费用报销都过一下」→ 过审预览，有令牌，人点才过账。
3. 「恒通电子有哪些工单？」仍现查，不是写。
4. 「把这张报销过审」仍过审预览。

1 不过 = 本篇没过。
