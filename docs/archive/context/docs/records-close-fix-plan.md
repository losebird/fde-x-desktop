## 1. 什么时候把表交给右边

一轮 = 你按发送，到会话自己说这一轮结束。

- 结束以会话为准。不听共享槽变了没有，也不在停转后再去读槽里最后一张。
- 过程里过闸的表不画。右边保持上一轮。
- 结束时交的是这一轮的正式结果，不是槽里最后一次写入。
- 模型自己再查不能把这一轮拖住。拖住了就不能把表交出去，而且必须让这一轮关得上。
- 这轮不是业务操作：没有表可交，右边保持原样，不换、不清空。
- 行内改行、过审、取消、点历史不走这一轮，保持现在的做法。

## 2. 正式结果里是哪些行

先绑对象，再绑条件。

- 用词表里的最长名称绑对象。被长名占住的字，不再拆成条件，也不再当成另一个短对象。
- 只说了短名：短的是别名就绑长对象。两个都是独立对象又分不清，先选再继续，不默默挑长的。
- 对象名里面夹着的枚举词，不再额外当条件。要收窄，得是对象名之外又说了的条件。
- 剩下的枚举，加到已经绑上、并且拥有这个枚举的每一个对象。不加到没绑上的对象，不按「附近」猜。
- 同一段字只绑一次。长名优先于枚举，也优先于更短的对象名。
- 一个条件在多个已绑对象上各有枚举：各自加上。只在一个上有：只加那一个。字段对不上是不是同一个意思：不加，这句不能假装已经筛过。
- 同一字段多个值是「或」。互相排斥又被说成必须同时成立：结果是空，空就显示空。
- 否定只认词表里的枚举否定，不靠猜最后两个字。
- 去掉三道猜测：前缀丢弃、归到附近种类、写死的字段名列表。
- 有关系又有条件：行必须在这条关系上，并且符合它自己那个对象的条件。不能只按条件把整个目标表拉下来。
- 关系的上游不能只用第一页的编号去找下游。
- 词表没有这个枚举字段，或图上没有这条边：这句没有可执行的条件，不从名字里猜，不编边。缺的以后从连接器补进词表和图，不在这刀写死。

自由文本、日期、金额不新做理解。对不上词表枚举和图的，不能编条件。

## 3. 行数怎么算全

不准把命中一次全灌进右边。

- 右边可以翻页。每一页都是同一个命中集合。翻页不能换成另一次没条件的查询。
- 页脚是这个命中集合的总数，不是这一页的行数。
- 到了查询上限，标明不完整。禁止把上限印成「共 N 条」。
- 业务库给不出总数，标明未知，不拿留下的行数充总数。

## 4. 怎么验

功能要过，行也要对。只核能跑、不核行，不算过。用现场词表里的对象和关系，不把例子写进代码。

- 同一条对话两句：每句结束，右边是这一句；过程里自己再查不换表；左边能停。
- 新对话一句带关系的现查：右边是关系上的行，不是目标表的默认一页。
- 说的是长名：不把长名里面的词再当成条件。
- 一个条件对上多个已绑对象：每个拥有它的对象都带上；对不上的不加。
- 没有枚举的关系现查：页脚不是「一页的长度冒充总数」。翻到下一页仍是同一批命中。
- 有关系又有条件：不在关系上的行不出现。
- 闲聊不换表。改行、过审、取消、点历史仍走原路。
