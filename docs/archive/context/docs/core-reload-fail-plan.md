# 重载核心：怎么收

对照 [重载核心为什么无效](core-reload-fail.md)。

权威是：核心那个口现在能不能接上。进程还在、口已经没了，就是死了。不要只认「手里有没有孩子」。

先补缺陷，再靠补上的路把本机核心带起来。不要把杀进程、手启 4318 当成修好。不写死端口号、不写死 pid。现查、改行、过账、设置保存不拿重载当开关去改。

## 1. 监督

复用已有核心的那条路，和另一条启动路认同一句：口不通就是死了。孩子还在、口没了：杀掉再拉。不要再卡在「child 非空就不 boot」。

不要另做一套「其实已经死了」的判断。口通不通，用现有探活，不要抄第二套。

## 2. 重载按钮

最需要重载的时候，核心口已经没了。按钮不能只把「请重启」发给已经死掉的核心。还活着的开发监督必须收得到，并走上面同一句：口不通就杀掉再拉。

核心还活着时，现在能用的重载不能被改坏。

## 你怎么验

改上之后。口已经没了时，点重载核心：设置里核心接通，不再 Failed to fetch。核心本来就活着时，点重载：核心仍接通，会话和适配器还在。现查、改行还能走。不要留下孤儿进程占口。
