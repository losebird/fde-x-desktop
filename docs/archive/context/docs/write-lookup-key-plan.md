## 为什么会这样

找行做成了两套。

预览和写后读回（`probe`）认你已经对准的那一行：令牌上的号是长数字，就按 schema 主键去对，对上就放行。所以左边会话、确认面都是对的，库里也有这单。

过账（`writeDest`）不认这一行。连接上的业务号列空着时，拿词表第一格做唯一滤法，单列等值，**不加主键**。这一格空着，`pickNo` 把令牌号退成主键，滤法就变成「业务号 = 主键」。没有任何一行的业务号等于主键，0 行。接口仍回成功。

改行还会再 `probe` 一次：按主键读回还是旧字段，对不上补丁，才写出「业务回了，但字段还是旧的」。删除、过审同一套滤法，0 行也当成功，只是没有这句红条。

新建不找行，没有这套。

不是这单不存在，是**已经对准的行，过账另找一遍**。

## 怎么收

权威是已经对准的那一行。改行、删除、过审共用。

1. 预览已经用主键对上的，过账必须按 schema 主键改/删这一行。不要再拿空的业务号去等值。
2. 预览是靠业务号对上的，过账才用那一格，且那一格在行上有值。
3. 0 行的 update / destroy 不得当成功。改行读回对不上补丁，就失败，不许「回了但没改」。
4. 不另起一套查找。`probe` 和 `writeDest` 用同一份身份。

## 收成什么样才算好

会话里选定 `388468591099904` 这种主键行、工单编号为空：点确认后这一行被改到，读回四格对得上，没有「字段还是旧的」。删除、过审对准同一行，删的/改状态的也是这一行。新建不变。
