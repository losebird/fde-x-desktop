# 业务应用可生产方案

第一性原理：**业务应用可生产使用、可稳定运行。**  
依据：[业务应用模块缺口](biz-app-module-gaps.md)、[Qwen 慢能收什么](qwen-slow-runtime-plan.md)、[Qwen 为什么特别慢](qwen-slow-runtime.md)、[原话定动作](speech-action-authority-plan.md)、[小模型业务格子](small-model-biz-ops-plan.md)、[项目上下文](project-context.md) 决策 15 / 17 / 22。Ace 已确认意图并说按第一性原理改。

三件已经对过的事收成**一条**方案，不是三份补丁：小模型出表后空转、手册/知识库/流程与业务闸分轨、业务应用三页没收口。

点头之前不改的是**后面几刀**。第一刀按本篇「第一刀」落地。

## 1. 第一性原理（先锁）

可生产、可稳定，拆成四条铁律。后写的功能服从这四条，不另起权威。

1. **这一句只有一个正式结果。** 现查 ok、表已上台：这张表就是答案。写：人确认过的那一张令牌才过账。手册、图、`search_text`、模型第二枪，都不是正式结果。
2. **真值在连接器，结构在词表/图，规章是当时。** 手册/知识库/流程可以解释「该怎么做」、可以问人，不能改库里的字段。现况必须 `biz_preview`。决策 15。
3. **模型是提示，闸是权威。** 无写动作 role → 现查。同一句同一 hop 已结算 → 不再 preview。失败、未绑定、人要下一页、写令牌，仍允许多步。
4. **做完就停。** 硅基 27B 单步变不快。能收的是已结算之后的工具环。不靠 prompt 想短一点，不把测试改成只用 grok，不拿超时硬掐，不取消思考。

「不改坏现在能用的」服从铁律 3：收口只切**已 ok 的现查 + 已上台的同一 hop**。第一次看似 ok 但查错（对象错、该 hop 没 hop），同回合仍允许纠；不能做成「本回合出过任何一张表就禁止再动」。

## 2. 现在到底差哪一层（不要再报清单）

| 层 | 现状 | 不稳还是未齐 | 本方案怎么收 |
|---|---|---|---|
| 查完不收口 | 21 行在 +104s 已回，后面 7 分钟空转、重复 preview | 不稳（体验）+ 浪费 | **第一刀** |
| 右表权威 | SSE / `lastEmitted` / 官方回合表三路合并；同 SHA 工单 21 能抖成客户 0 | 不稳 | 第二刀 |
| 写确认回读 | 预览能发牌；确认 → 库 → 表和审计 未整包锁死 | 没锁死 | 第三刀 |
| 手册/知识库/流程 | 会话可连用；闸不认规章；无顶栏「知识库」「流程管理」 | 未结合，不是抖 | 第四刀（只接「当时」，不接写） |
| 应用壳 | 创建管道能跑；观感/能力条/目录未齐 | 未齐，不是抖 | 第五刀。稳定运行不靠这一刀 |

操作记录页能搜能翻。顶栏代写绕过审计，进第三刀，不是小尾巴。

## 3. 不做什么

- 不把 27B 变快，不换测试模型，不关思考，不流式当修好。
- 不新建顶栏模块，不嵌官方知识库/流程管理整页。
- 不写「手册第 X 条所以 patch 字段 Y」的写闸。
- 不写死工单、21、待审、停用、某一个台账名。
- 不在第一刀动 pending 三路合并、不改写令牌状态机、不改应用铺面。
- 不顺手重构全仓库。只删**本刀证明没人走的旧路**。
- 不把「第一次出表」当成结算，如果那张表是闸拒、空 kind、写预览、或 where 未绑。

## 4. 第一刀：查完结算就停（现在落地）

目标：现查已经 `ok`、有对象集总量、官方表已上台、同一句同一 hop —— **speak 写清共 N 条；禁止再打同款 `biz_preview`；模型再想再查当 leftover，该说的话说完，`turn/end`。**

### 4.1 改什么

权威放在闸 / 回合，不放在 prompt。

1. **回执带对象集。** `biz_preview` 现查成功回执必须能让模型看见「共 N 条，本页 M 条」。N 来自已有 `hitTotal` / 对象集，不是本页行数，不是写死 21。没有 known total 就说没有，不准用页内行数冒充。
2. **同句同 hop 不重复现查。** 判定键：本回合 utterance + 已结算 hop（型 + 已绑 where/关系），不是「本回合调用过 preview」。再打同一 hop 的现查：拒，回同一张表 + 已结算说明。人说「下一页」「第 N 条」、换对象、换 hop、或上一跳未结算（UNBOUND / 空 kind / 问人）：仍允许。
3. **已结算现查 → leftover 收口。** 官方表已 apply 到业务记录、现查 ok：继续 `biz_preview` / 同 hop 补查当 leftover。该说的话说完，不要再开工具环。写预览令牌、未上台、失败路径：不走这条。

### 4.2 删什么

只删证明是空转来源、且结算后不再需要的旧路：

- 已结算后仍建议 `search_text` / 再 `biz_preview` 的 catalog 跟句（与「有单号先 preview」不冲突：未结算仍可建议）。
- 同 hop 第二次现查若只是把同一 `preview_id` / 同一 hit 再 spew 一遍的包装函数，内联到「回已结算表」，删重复入口。
- **禁止**删：`recoverWriteIntent`、one-bind / `enumHits`、写令牌、UNBOUND 多步、`route_intent` 本身、文件 attach、记忆 `search_text` Host。

删之前：引用计数 + 现网路径。有测试或会话还在走的，先改调用方再删，不准留死导出。

### 4.3 不碰

写 `biz_write`、确认栈、`lastEmitted` 合并、应用 spec/铺面、手册 ingest、决策 22 已图过的 hop 主路径（回款∩合同等）的绑定算法。

### 4.4 安全 / 稳健 / 性能

- 安全：结算只对**现查**。过审/改/删令牌上台 ≠ 现查结算。
- 稳健：ok-but-wrong（36+166 拆开、对象错）——若模型改的是 **where/hop 绑定** 而不是同一 hop 再要一页，仍允许多步。只禁「同一绑定再打一遍」。
- 性能：少 2–3 次硅基往返（实测 step3–5 约 7 分钟）。工具本就 ~2s，不在工具上挤。
- 不硬编码：hop 键来自词表 kind + 已绑 clues，不写业务名。

### 4.5 怎么验

1. Qwen 新会话「停用客户还有哪些没关的工单？」：表上台后一两句内 `turn/end`，不要两遍同款 preview；现查仍是交集，不是目录页。
2. 第一跳 UNBOUND / 停用对不上：仍允许 replay 成词表枚举再查（grok 那条路）。
3. 「待审的费用报销」无写 role → 仍是现查，不收成过审令牌。
4. 「都过一下」仍走过审预览，不因「刚出过表现在结算了」被 leftover。
5. 人说下一页：仍可再查。
6. 回归：one-bind / 原话定动作 / where-by-cell / write-hop-actions 单测全过；不推远程。

## 5. 第二刀：右表只认这一句（不在本落地）

目标：废掉「三路 pending 谁后到谁上屏」。一句话一张正式表。空表、取消、假 kind 不得 hold 旧表或倒目录。

- 改：BFF GET pending 不再 `officialRoundSheet + lastEmitted` 合并；右表只吃本句正式结果。kind 资格收到连接器表（决策 15），图谱概念不得进 preview。
- 删：第二条 emit 管子里确认死的那条；取消后仍能把旧 `preview_id` hydrate 回来的会话存储，若正式结果已作废。
- 验：同会话连续「停用工单」→ 下一句，不得客户 0 盖工单；取消改行留 hop 表；模糊多名先选，一批不一家家问。
- 风险：这刀动右表权威，必须单独验四条契约。和第一刀拆开，避免把「结算」和「换表」缠死。

## 6. 第三刀：确认过账才算写（不在本落地）

目标：人点右栏确认 → 库 → 官方表回读 → 审计一条。预览不是写。

- 改：成功过账拉官方现况，不准琥珀条留预览行；幽灵令牌 / 已取消 `preview_id` 不能再确认；操作单顶栏执行必须进同一审计，不准 `workstation` 旁路。
- 删：确认栈里第二份可确认副本（已有契约、现网未死净的那几份）；W24 取消后复活的 sessionStorage 回放。
- 不把手册条文写进 patch。
- 验：W 集确认/过账/取消不复活；无确认拒写仍在。

## 7. 第四刀：规章是当时，不是写权威（不在本落地）

目标：工作区制度/手册、记忆（知识分类/决策/摄取）能**帮助决定查什么、问什么**，不能写库。

- 改：未结算前，允许同一回合 `search_text` / 附件 / 记忆 find 作为「当时」。catalog 已经写过：有单号、在问现在库里怎样，不要先 `search_text`。结算后同样不许再搜来拖回合。
- 问人：手册与词表冲突，问人，不准静默按手册改字段。
- 不改：`biz_write` 只吃 preview 令牌；`context-pack` 继续只拼 prompt，不进 `/preview` body。
- 不新建「知识库」「流程管理」顶栏。记忆子画布保持原模块。
- 删：若有「search_text 结果直接当 write 字段」的死代码或实验钩子，删。
- 验：附件手册后现查仍走闸；没有令牌不能写；「待审+型」仍现查。

## 8. 第五刀：应用是产品页（不在本落地）

稳定运行不依赖观感。可生产「日常用台账」才做：能力长进动作而不是每卡一条 chip、目录纯化、无 `pages` 存量补 pages、规格 04 拖卡验收。创建管道已能跑，不准重做向导。

## 9. 删代码的总规则

每一刀结束时交一份「删了什么 / 为什么没人走 / 哪条测试锁住」。

- 只删本刀触及的死路。
- 旧 overlay 与 BFF 双实现：留下闸权威那一份，删确认不再调用的副本。
- 不许用兼容层「先留着」。决策 17：一次写完。
- 单测必须覆盖：结算后二次同 hop preview 被拒；未结算 / 写令牌 / 换 hop 不被拒。

## 10. 安全

- 写必须工作台确认。无 `source=workstation` 继续拒。
- 手册、记忆、流程、IM 先例不得成为 `biz_write` 真值。
- 不扩大 overlay 对官方 DSH 家目录的写入。`FDE_DSH_HOME` 仍是 `~/.dsh-fde-x`。
- 不把连接器密钥、会话全文打进 speak。

## 11. 性能

- 第一刀：去掉已结算后的硅基空转（主收益）。
- 第二刀：少一次错表再查。
- 第三刀：过账后一次官方回读，禁止再靠模型补查「写进去了没有」。
- 不在热路径加新的整图扫描；词表/图继续按 kind 取。

## 12. 落地顺序

| 刀 | 状态 | 谁验 |
|---|---|---|
| 第一刀 查完结算 | **本回合落地** | 单测 + 你用 Qwen 打第 4.5 节 |
| 第二刀 右表权威 | 第一刀现网过再开 | 四条契约原句 |
| 第三刀 过账回读 | 第二刀过再开 | W 集确认/过账 |
| 第四刀 规章当时 | 可与第三刀后并行，**不得**早于第一刀（否则结算定义会被手册检索打穿） | 附件+现查+无令牌不能写 |
| 第五刀 应用铺面 | 记录稳了再做 | 规格 04，不重做创建 |

## 13. 第一刀验收（你手打）

Qwen3.8-27B 新会话：

1. 「停用客户还有哪些没关的工单？」——表上台后很快结束；仍是交集；不要两遍同款 preview。
2. 「待审的费用报销」——现查，无过审令牌。
3. 「都过一下」——过审预览。
4. 若第一跳对不上枚举，允许再查，不准整回合锁死。

失败就停，不准接着做第二刀。不推远程。
