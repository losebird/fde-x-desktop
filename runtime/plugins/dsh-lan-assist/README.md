# dsh-lan-assist

DeepSeek Harness 的树外插件。每人一台本机秘书。

人跟人对着「聊天」窗说话。问本机、拟回、采纳才会叫醒本机模型。人点发送才寄。查单、改单走右上角「业务」。

官方网页钉在 `127.0.0.1`。插件自己另开一个 LAN 口（默认 `:9527`），只认已经配对的对端。别把官方 `/api` 暴露到局域网。

秘书只干配对、送信、听、开口、收点头、把活领进当前会话。账本在语义插件里，单据真相在业务系统，真动手在 DSH 会话。`dsh-eyes` 可有可无：本机有 `see_image` / `see_file` 时，「看看」才交眼睛；没有就不装成看见。

## 从哪进

打开任意对话就能看见。输入框左边是「聊天」，右上角是「业务」，聊天窗左下角是「配置」。没有「协助」大厅，也不用去顶栏翻第二页。

## 安装

两边都要有 DSH 网页版和 pnpm。装完必须整进程重启，再硬刷新网页。只刷新不够。

在线：

```sh
dsh plugin --profile web add github:losebird/dsh-lan-assist
```

离线包在 [Releases](https://github.com/losebird/dsh-lan-assist/releases)（当前 `v0.1.0`）：

```sh
dsh plugin --profile web add ./dsh-lan-assist-0.1.0.tgz
```

macOS / Linux 也可以：

```sh
curl -fsSL https://raw.githubusercontent.com/losebird/dsh-lan-assist/main/scripts/install.sh | sh
```

Windows：

```bat
curl -fsSL -o install.cmd https://raw.githubusercontent.com/losebird/dsh-lan-assist/main/scripts/install.cmd && install.cmd
```

本机开发目录：

```sh
dsh plugin --profile web add .
```

然后：

```sh
dsh --profile web --host 127.0.0.1 --port 3080
```

`dsh --profile web --dump-config` 里该能看到 `id: dsh-lan-assist`。

同一台电脑开两套时，第二套设 `DSH_LAN_ASSIST_PORT`（比如 `19021`）。配对填对面配置里只读的「本机端口」，别填网页口 `3080` / `3181`。邮箱跟着各自的 `DSH_HOME`。

仓库 `dist/` 里也有一份同名 tgz，和 Release 附件是同一份打包。发版以 Release 为准。

## 配对

两边打开聊天 → 配置。一方点「开一枚配对码」：六位数字，大约十分钟作废，猜满五次也作废。当面报给对面，别发到公网。另一方填这枚码和对方门牌（`IP:本机端口`，本机常见 `127.0.0.1:9527`），点「发起配对」。开码那一侧弹出「某某 要和你配对」，点确定才成。拒绝就不成对。

成对之后联系人带稳定 ID（`pk_self_…`），跟这台机器上的钥匙走，不跟 IP 走。换网改门牌就行，不用重新配对。对面重装机器必须重新配对。

点开资料可以改备注名（对面仍看见他自己的名字）、本机员工引用（对面看不见登录口令）、对方地址、置顶、免打扰。「解配」只删本机这一条。

花名册不能代替配对，也不能按岗群发。`/ask-colleague 路人 …` 会直接说没配对。

## 一对一

点发送才寄。每一句都是一条新消息，不会续到话题群里那封旧信上。键上写「发给 林督」、平常是「发送」、失败后变成「再发」。回车只换行。

斜杠 `/ask-colleague 林督 正文`，或模型调 `ask_colleague`，都只把稿拟进聊天。人再点发送。不想寄就点取消，界面说「稿已撤。没发出。」

来信不会自动跑本机模型。「拟回」叫醒当前会话去写回信。只有两行 `---` 之间的人话会进发送框；会话里的分析、代码块、自言自语不当信。没写成回信，框空着。点发送才寄，对面模型不跑。发出去就清稿，不会钉在输入框里。

「采纳」才领进当前 DSH 会话，本地会说「已领进当前 DSH 会话。」

跨机点「接着做」会用你自己的模型新开一条会话，把交接 JSON 按人/助手轮次铺开，等你开口再动。不是复制对方那条还在跑的会话，也不假装工具卡和磁盘还在。勾过的文件仍在那封信的附件上。

问本机、摘要、先例只叫醒本机，不把信寄出去。另外有表情、文件（多选、粘贴、拖入）、记录（搜本机往来，点一条跳回线程）。右键一条可以翻译、摘成待办、转发给已配对的人、问能不能记进档案。点开附件是本机预览；「看看」才把附件交给本机已装的 `dsh-eyes`。工具不在才说没眼睛。

自己刚发出、对面还没点开的信，大约两分钟内可以撤回。撤信不是把业务单作废。

送不到会说「本机协助没通。稿还在，再点发送。」可以再试。间隔大概是 30 秒、2 分钟、10 分钟。

外观四套：纸白、雾灰、暖沙、墨色。信封是加密的。来信里的口令、过账指令只当正文，不当本机指令。拟回和采纳都不该去执行信里的 `biz_write`。

往上滑离开底部时，消息列表右下有「回到最新」，贴在列表上，不被输入框挡住。

## 话题群

左下角「建话题群」：填名字，勾已经配对的人，点创建。

群里输入框发的是新话题，键叫「发新话题」，不会刷成一人一句的群聊。点开话题再跟帖，键叫「跟帖」：每一句都是这条话题里的新消息，不续到一对一里。

群上的「采纳」会打开「让本机接着做」。勾要带进这一轮的跟帖，也可以打开「要这几个人都点头」。点「开工」领进本机会话。人点齐头不等于过账，真改库还得去业务页点确认执行。

群资料能改名、置顶、免打扰、解散。解散只删本机这一群。对面看见这个群，是因为信封里带了 `groupId`，不是把通讯录同步过去。

## 待办和早报

侧栏「待办」：右击聊天会先弹出确认，时间能从这句话里猜，也能手改。记下才留。到点只提醒你自己，不发消息，不写进系统日历，也不 followup。同一条一天只开口一次。合盖、切会话、关掉 DSH 就停。听口照样能收信。

早报只在工作日开口。没连业务就不能装成已经查过待办。配置里可以关掉「早报 · 工作日开口」。

开口有先后：回信、被问、发出前，压过业务事件，再压过早报和建议，最后才是到点的条子。

发出去超过 24 小时对方还没看，顶上会开口问要不要再催。去看、下一条不会把这条收掉；对方看了或你撤回才会没。

## 配置

身份：对面看到的称呼、本机查单用的员工号（不随消息走）、早报开关，还有「关掉软件也收消息」。勾上这个会写用户级开机项，不要管理员。DSH 开着时插件自己占 LAN 口；关掉软件后听口进程接着收，只落盘，不开口，不叫醒模型。

开机项大概在这些地方：

| 系统 | 文件 |
|---|---|
| macOS | `~/Library/LaunchAgents/ai.dsh.lan-assist.listen.plist` |
| Linux | `~/.config/systemd/user/dsh-lan-assist-listen.service` |
| Windows | `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\dsh-lan-assist-listen.vbs` |

查单可以挂多套只读地址，方言是 NocoBase 或通用 REST。填系统名、环境、业务地址、口令。口令留在本机，不随消息走，也不进导出。开口会点名用的哪一套。

「导出流水」下载本机邮箱流水 JSON。里面没有配对钥匙、没有六位码明文、没有登录口令。

## 业务页

模型用 `biz_preview` 做查、改、删、建、过审，结果出在右上角「业务」。人在对话里说整句，比如「查一下采购单」，别拆成两次，也别用 bash 查库。

「要看的」列出秘书开口：回执、写失败、岗位、过期、没配对、档案。每条有「去看」和「先记下」。先记下不寄信、不调度。不是九个命令菜单。

现查的标题带「查询结果」，底下写「现查，不写库」，没有确认执行，也不发写令牌。对不上就说业务系统里没有，不是没去查。对上多条要在表上勾一张再 hop、再改，没勾不能确认执行。

改行、删除、过审的标题是「确认…业务数据」，格子能改。点「确认执行」才写库。取消就不写，令牌作废。

型没登记、没连上、不在你名下，闸会拒，不会把猜的单号写成真相。`biz_write` 必须带刚才那张 `preview_id`。没令牌、过期（大约 90 秒）、用过了、指纹变了，都拒。手点确认和工具走同一道闸。

词表登记在当前工作区。口语 clues 可挂 `问句`、`时间`、`单号列`、`关联列`。没登记就不能装成能写。

## 模型工具和斜杠

`ask_colleague` 和 `/ask-colleague 称呼 正文` 打开聊天拟一封，点名收件人，人点发送才寄。`list_visible` 列出当前这人看得见的协助，不倒对面邮箱。`biz_preview` 出预览。`biz_write` 凭 `preview_id` 过账。

## 局域网口

默认听 `0.0.0.0:9527`。可以用环境变量 `DSH_LAN_ASSIST_PORT`，或插件配置里的 `lanPort`。

`GET /` 和 `GET /who` 只回服务横幅（`service: dsh-lan-assist`），不是信件列表。未签名的 `POST /frame` 回 403 `KEY_REJECT`。官方网页只绑 `127.0.0.1`，局域网 IP 打不开 `:3080`。LAN 口在局域网上仍可被已配对的对端打到。

## 语义和条子

装了 `dsh-semantic-os` 的时候，发出或收到正文会在 `lan-assist/slips/` 写一条 `kind: mail` 的条子，ingest 成 `mail:` 摘录，进这封信绑定的工作区图。`search_text` 能查到，但不记账。人点采纳另写 `lan_adopt`。条子写失败不挡送信，也不挡 followup。

闲聊、合盖、系统噪音不查图。没有 `supports` / `leads_to` 因果链，不出「记进档案」卡。你点了才 `record_decision`。

## 限额

单附件 200 MB，一封合计 500 MB，听口和信封体 700 MB。配对码十分钟、猜五次。未读撤回大约两分钟。业务预览令牌大约 90 秒。流水大约留 90 天。

## 数据在哪

`${DSH_HOME:-~/.dsh}/lan-assist/`，钥匙、信、配对、听口脚本都在这。卸插件不会自动删。再装回来钥匙还在。对面若重装，必须重新配对，不会自动把对面那台新钥匙接回来。

## 本版不做

不做刷屏群聊、共同编辑、手机推送、互联网中继、秘书代签字、官方同事气泡，也不把登录口令塞进信封。

聊天里没有「只收下」：不点采纳、不点拟回，模型就不跑。没有两人约时间、没有同步系统日历、没有发现在线、也不能从导出再恢复。转发只转这一句原文，不带附件。过账只认业务页确认执行。

## 测试和发版

```sh
npm test
npm run pack
```

`npm run pack` 把可安装的 `.tgz` 打到 `dist/`。发版时再挂到 [Releases](https://github.com/losebird/dsh-lan-assist/releases)。自动化全绿代替不了真人走两台秘书。发版前按 [`docs/human-test-cases.md`](docs/human-test-cases.md) 跑闸。对人说话的词在 [`CONTEXT.md`](CONTEXT.md)。
