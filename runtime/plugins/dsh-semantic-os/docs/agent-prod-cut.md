## 五类怎么算修好

| 总判 | 修好 |
|---|---|
| 帮不上忙 | 人用该 ID 的原话/原键，不改词，第一条就能办事。对话和页面能对上的必须同类。 |
| 坏 | 假成功、写脏、拒错、双口一个有货一个空、主账回滚假成功，全部消失。该拒的拒，该写下的真写下。 |
| 入口缺 | 键在能点的地方（不是藏进管理页）。点了是对的页/抽屉/下载，不是 404/501。 |
| 空柜 | 口通。这张图没货就诚实空，文案能看懂下一步。不装过关、不装坏、不编数据。侧栏写「图里没有」而 `search_text` 有货 = 帮不上忙，按帮不上忙修。 |
| 不可用 | 缺依赖/缺第二份/缺版本时，人看见「没装这套依赖」或「还没有版本」，并有可点的下一步（装、生成第一份、回词表）。不转圈、不 501。 |

性能：对话 ≤3s，页面 ≤5s；5 路检索不互锁。安全：Origin、cwd、点头、仓外、PII 该拒的拒。活路径不写死模型 URL、端口、缓存戳、假路径。
